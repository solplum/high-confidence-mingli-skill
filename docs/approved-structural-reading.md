# 已批准的八字与紫微结构增补 v1

## 入口与证据

默认建档与解读输出已接入两个独立面板：

- 八字：`bazi_core_reading.reviewed_structure`，由 `scripts/bazi_reviewed_structure.py` 使用核心模块已核的四柱事实、候选、冲合、强弱证据生成。
- 紫微：`ziwei.rule_output.reviewed_structure`，由 `scripts/pai_pan_ziwei/reviewed_structure.ts` 使用原始本命 chart 生成。JSON 与默认文本使用同一对象。

两层新增字段，不改原始四柱、星位、亮度、四化表、旧格局或旧强弱结论。源文件为 `references/approved/` 内两份项目释义，原始八字/紫微参考保持字节不变。登记增加2份项目释义来源、11条原子记录，对应9项已批准范围；它们不是11份独立经典证据。

开始仍运行 `python3 scripts/knowledge_catalog.py validate`。按需查询：

```sh
python3 scripts/knowledge_catalog.py query --system bazi --profile bazi-reviewed-structure-v1
python3 scripts/knowledge_catalog.py query --system ziwei --profile ziwei-reviewed-structure-v1
```

这些条目用途为 `conditional_module_only`：个人报告可解释面板提供的关系、条件和观察主题，并按 [解释方法 v2](interpretation-standard.md) 作作者现代转译和条件综合，保存原始面板、人工解释及审阅记录；不将条目转为通用个人 ledger rule。现有 ledger 会明确拒绝该用途。原有 ledger 权限和经典引用门没有扩大。

每卡保存实际节点/星位路径、条件、排除或反证、具体未知和引用。引用包括本地释义的行号/hash、版本、许可，以及原扫描页或固定文档段落。`conditional` 是给定输入下可讨论的方向或问题，`withheld` 为缺条件/来源/输入等暂缓；紫微 `structure_only` 仅说明坐标或类型核对，不比 conditional 更可靠，也不证明现实效力。

## 八字 BZ-K01～04

| 卡片 | 实际增加 | 保留的未知 |
|------|----------|------------|
| BZ-K01 | 对每个正官候选列官受伤、印制伤、印受财制/干合及月支条件，区分透印和藏印 | 印出现不证明有效救应，仍不判成格/破格 |
| BZ-K02 | 食制杀、印制食、财制印与财生杀逐节点列方向，同一财的反向作用保留 | 不把伤官当食神，不裁决哪条占主导或已有效制杀 |
| BZ-K03 | 五合是否含日干、他干角色、中间干和共享端点按柱位列出 | 不因相邻、隔位或共享配对断合去、合绊、合化 |
| BZ-K04 | 各候选的月令观察中心、相神候选对象与扶抑语义分别说明 | 不输出唯一喜忌、调候或幸运五行 |

所有方向节点均保留透干/藏干层级与根的位置；“有同五行藏干”不保证作用有效。并列月令候选不会为满足某卡而被删除。来源为1926单版影像的原创项目释义，核查页范围见卡片；不冒称多版本校勘或古书布尔算法，也未改编既有 CC BY-SA 十卡。

时柱未知或中心输入存在非零时间误差时，新面板暂缓个人结论，仍列实际已知事实。候选枚举内，每张面板有 `scenario_id` 并只对该候选输入成立；这些卡片没有被纳入区间稳定性证明，不能把某一个候选的解释外推全区间。

## 紫微 ZW-K01～05

| 卡片 | 实际增加 | 保留的未知 |
|------|----------|------------|
| ZW-K01 | 本宫空宫定义、实际辅杂曜、对宫主星源路径与借星元数据核对 | 空宫星性仍暂缓，不继承亮度/四化或当作实坐 |
| ZW-K02 分组 | 十四辅星独立分组与实际范围，旧 Star.type/四煞不变 | 不按吉煞星数判好坏、权重或抵消 |
| ZW-K02 辅弼 | 辅弼实际同宫时，直接介入与间接配合的可反驳协作问题 | 辅弼自身未登记四化修饰、输入等缺口时暂缓，不保证贵人 |
| ZW-K03 | 仅机梁两主星实坐命宫、亮度和本宫修饰检查满足时提出联合问题 | 不从三方凑齐或借星触发，不定格名、人格、职位 |
| ZW-K04 | 十二目标宫的实坐、三合、对宫、两侧邻宫与指定两星夹结构 | 不判夹拱吉凶、倍率，也不改旧格局匹配 |
| ZW-K05 附着 | 生年干→本命化类→实际星名/位置，40格固定表逐格核对 | 禄存/动态/自化不替代本命，错配不补造 |
| ZW-K05 化禄 | 实际本命主星化禄的已登记主题增加问题，同时问成本与消耗 | 不解释为收入/好运，未登记同宫多化修饰等条件下暂缓 |

辅弼和化禄主题只在当前已登记的命财官迁领域使用，其他宫保留结构与具体缺口；机梁主题只在命宫。三项均是现代资料支持的观察问题，现实反例或更直接的职责、资源、训练等解释可使其不适用，不写成已测得的个人特征。

非零出生时间误差由总控传到新增紫微层，三个观察主题均暂缓；坐标表仍只是这个输入候选的计算事实。直接紫微 CLI 的 `--temporal-uncertainty` 同样保留此标记，不改变原始 chart、旧 domain 或旧格局。完整星表、四化修饰与来源条件分别检查，不能以字段漏标作为“没有修饰”的证据。

## 如何使用新增深度

按本次问题选择卡片，正文说明本盘具体节点如何支持或反向制约，哪些条件已核、哪些效力仍未知，以及什么现实情况会推翻观察主题。完整坐标表按需查 JSON；不把整包重复注入或把自动面板原样复述当成完成详批。沿共享流程继续检索、竞争解释和单独复审。

八字四卡的自动输出仍审盘面结构。用户现已批准按统一解释方法，将其实际关系转成有依据的现代做事/协作含义，并形成条件综合，无须逐词登记。作者解释与卡片原文、自动状态分别保存，不冒称古籍人事象义或已测人格。紫微三个已批准主题可展开为充分的条件解释，保持各自领域、星位与修饰前提；人工解释的空间与实质缺口按同一方法处理。

来源发生变化时先重新验证，保留原版本，不用新旧释义拼接。资料校验失败必须明确失败；旧模块仍遵守原有全目录门，不因新增面板而默默绕过。

本轮不启用 BZ-K05 四库冲效力、自动成败救应、唯一喜忌、吉煞权重、借星继承四化/亮度、飞化自化或人生事件预测。新增层主要提高结构分析的细致程度；先前真实赛事题的拒答基线不能自动被当成预测能力提升。外部案例与答案继续只在独立评估目录保存，保留集需明确选择才使用。
