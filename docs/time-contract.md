# 时间契约与回归

## 兼容与选择

`build_chart.py` 默认 `--time-basis civil --utc-offset 8`，保留旧版八字/紫微的民用钟面结果。选择 `--time-basis apparent-solar` 才将经度与均时差修正后的**日期和时间一起**传入八字日时柱及紫微。太阳钟面是无时区标签，不是第二个物理瞬间。节气、年/月柱、起运距离和七政天体位置始终基于输入的原始瞬间。

`--utc-offset` 是出生当时实际 UTC 偏移，不是时区名称，也不会自动校验历史夏令时。固定偏移以小时数输入，实际偏移须为整分钟。例如 `--utc-offset 8.333333333333334` 对应 UTC+08:20。换算时只消除浮点表示误差。太阳钟面 = UTC 钟面 + 经度 × 4 分钟 + 原七政引擎均时差。显示到秒不表示秒级精度；此次仅修复数据流和日期进位，没有独立测定均时差误差。计算日时/紫微时向下取整到分钟，避免显示四舍五入造成偷偷越界。

已核民用时区或偏移时，民用钟面的八字、紫微和出生误差候选可省略经纬度。平太阳时和真太阳时需要经度。缺经度时，JSON 的 `time.mean_solar` 和 `time.apparent_solar` 为 `null`。七政命度、立命宫、昼夜及恩用难仇沿用引擎的经纬度要求，缺任一时保留仅依赖出生瞬间的星曜位置。七政敏感性需两项坐标均已核实。

- 八字保留原有 23:00 换日规则。
- 紫微保留原副本子时索引 0 的处理；晚子时与八字换日可能不同，输出警告，不擅自统一学派。
- 七政保持现有体系，包括安命用 +08 民用时辰；太阳模式不意味着七政所有规则已改为太阳时。
- `--uncertainty-minutes N` 表示 ±N 分钟输入误差。非零时结果明确标记为中心时刻候选，未开启 `--enumerate-scenarios` 时不枚举候选，不得把它当唯一确定命盘。
- `--age-year YYYY` 指定紫微公历目标年，按目标年减原始民用出生年加一取年度虚岁，生日和春节均不参与年龄递增。文本保留虚岁段并列出以原民用出生年计算的公历半开窗，标记该年所处大限。未落入已列大限时明确提示。有出生误差时表格只代表中心盘。JSON 的 `currentAge`、`currentDaXianIndex`、`isCurrentDaXian` 沿用旧字段名，仍以目标年为准。
- 紫微内部 `--birth-year` 仅传递太阳钟面跨年之前的原始民用出生年，不改变排盘日期。

## 运行

Python 3.8+；紫微使用 Node 18.19+（`--import tsx`）。先在 `scripts/pai_pan_ziwei` 运行 `npm ci`。总控只使用本地已安装依赖，不再通过 `npx` 在缺包时自动联网下载执行。依赖缺失则明确降级。

```
python3 scripts/build_chart.py --solar 1986-01-04 --hour 00:10 --sex 男 --lat 30 --lon 90 --utc-offset 8 --time-basis apparent-solar --age-year 2026
python3 scripts/test_pai_pan_bazi.py
python3 scripts/test_pai_pan_qizheng.py
python3 scripts/test_time_contract.py
```

测试样例使用明确合成的日期与纬度30°、经度90°，不对应个人出生资料。固定+08转90°平太阳钟面恰好减120分钟，因此为前日22:10；该瞬间按现行固定均时差公式得约−4.533分钟，真太阳钟面为前日22:05:28，传入日时/紫微时向下取整至22:05。回归测试验证日期和时辰传递，而不是验证命理解读或天文绝对精度。新增测试还覆盖立春瞬间不被太阳钟面平移、跨年、非法日期、误差提示、警告保留、目标年份大限及虚岁边界。紫微依赖缺失时其测试会显式 skip，不能宣称全套通过。

## 对照审查与未解决事项

对照了 `fortune-observatory@3ce1995e41b29e4ab2320323a969158f4e5b2214` 的时间服务、八字服务、节气测试和紫微限运接口，没有移植其实现：其 DE440s 数据与依赖更重、部分时间口径元数据与代码不一致，且七政体系不同。不将其差分测试数量当作独立金标准。

七政默认 `physical-v2` 按出生瞬间的太阳中心几何高度判昼夜，采用 −0.833° 阈值。旧钟面混用问题限于历史重放的 `legacy-v1`。全球地点覆盖、独立历表与星历参照、历史时区、三盘完整误差和跨流派子时口径仍有各自的核查范围。七政升度与相关误差见[地平计算契约](qizheng-horizon-contract.md)。回归测试只覆盖所列实现契约。

## 全局分析年份

总控新增 `--analysis-year YEAR`。显式提供时八字 `current_year/current_gz/liunian_years` 与紫微目标年共同固定，不更改出生瞬间、四柱或天体位置。年份须不早于出生民用年且不超过 9999；与 `--age-year` 同时提供必须同值。

未提供时保持旧接口：八字取运行当年，紫微由 `--age-year` 或运行当年控制。JSON `provenance` 分别记录 analysis_year、resolved_bazi_year、resolved_age_year；不会把未固定的年度伪装成统一。默认文本中的建档日期仍为实际运行日，不属于分析日期。完整 JSON 在相同代码、依赖和输入且显式固定分析年时可跨运行年份复现。

`current_gz` 是所选公历年份的年度标签（例如 2025 → 乙巳），不是该年 1 月 1 日按立春换年的即时年柱。内部传给八字 `now` 的 1 月 1 日仅用于传递年份，不是新增事件时刻；出生年/月柱仍按原始出生瞬间判节气。

独立八字文本将该值显示为公历年度标签。要判断某一天的年柱，用下节查询入口按实际立春时刻核对。

## 八字查询时段事实

民用查询区间左含右不含。按固定偏移查询时，两端传入同一固定偏移。知道查询地的 IANA 时区时，显式传 `--timezone`，以实际民用钟面解释起止并切分偏移变化。

```sh
python3 scripts/bazi_period_facts.py --start 2026-11-01T00:00+08:00 --end 2026-12-01T00:00+08:00 --layer month
python3 scripts/bazi_period_facts.py --start 2026-11-01 --end 2026-12-01 --timezone America/New_York --layer month
```

- `--layer year` 按实际立春切分。 `month` 再按实际节气月切分，`day` 另核民用钟面 23:00 换日。
- 两端都用 `YYYY-MM-DD` 并指定 IANA 时区时，默认覆盖当地起点日期到终点日期前的所有可达时刻。午夜跳时、整日跳过和历史回拨按真实日期成员处理。输出 `civil_dates` 记录原日期范围，`segments` 按 UTC 顺序列出实际覆盖。回拨若使所问日期间插入其他日期，`civil_date_membership_gap` 标记实际空档。此时顶层 `start` 和 `end` 只给首段起点和末段终点，实际覆盖以 `segments` 为准。续算 QX 时逐段用 `segments[].start` 和 `segments[].end` 构造 `expected_window`。整个日期范围均不可达时报错。需要指定钟面或 fold 时用下述端点方式。
- `segments` 给每段起止与所选层及上层干支事实。节气按物理瞬间计算。IANA 查询在偏移跳变处切段，上一段终点与下一段起点可显示为不同钟面，两者对应同一 UTC 瞬间。逐段使用段内固定偏移，遇跳过或重复的 23 时按实际可达的当地钟面重算日柱。
- 八字和紫微长区间从解析钟面所用的同一份 TZif 核取显式切点；可核的固定尾段或常见 POSIX 循环月规则也按实际偏移检查。无法可靠建立索引的区间继续逐个整数 UTC 秒核查。查询保存所用时区来源的摘要，起止、闰月、跨年、历史秒偏移与已有分段合同一致。
- IANA 起止可传当地无偏移钟面，或同时带与该地相符的实际偏移。无偏移的重复钟面须分别通过 `--start-fold` 或 `--end-fold` 指定 0（较早）或 1（较晚）。不存在的钟面和冲突偏移会报错。明确选择太阳查询钟面时，另按该口径核查。
- 查询分段只覆盖历法事实。大运起止、出生候选及所问领域方向分别核实。对 QX 模型逐段交付，保留大运未知和人工反证核查。

### 只有民用出生日期时的六字候选

`python3 scripts/bazi_scenario_reading.py --birth-date 2026-02-04 --sex 男 --utc-offset 8` 给出整天可达的年、月、日三柱与各自结构。月份和日期也可省略前导零，输出 `solar_date` 使用 `YYYY-MM-DD`。若指定 `--timezone`，程序按该日实际偏移分段，保留重复钟面的各段并识别跳过的整日。使用日期所在的实际民用时区。

JSON `windows` 左含右不含，按节气和 23 时换日切分，并用 `candidate_id` 回指 `candidates`。逐候选读取 `analysis`，只在相关条件和结论均一致时报告共通结果。全部候选都保留未知时柱，也不把各段起点用作出生时刻或交运依据。该入口的覆盖限民用钟面与原三柱模型，明确采用太阳时的情形另核，天文模型与历法近边界的误差也仍需保留。

### 已知民用时辰时的四柱与起运候选

原公历民用生日和民用时辰均已确认、分钟未知时，运行以下入口。示例使用合成输入和明确的 UTC+08。

```sh
python3 scripts/bazi_scenario_reading.py --birth-date 2026-02-04 --shichen 寅 --sex 男 --utc-offset 8
```

也可用 `--timezone` 核出生时区。程序只取该民用日期、时辰内可达的左含右不含时段，保留重复钟面的两段并跳过不存在的钟面。已确认午夜民用日期的子时取该日 00:00 至 01:00 前及 23:00 至次日 00:00 前，按八字 23:00 换日分别核对。日期或钟面口径仍有歧义时保留实际候选，已选太阳时继续按该口径另核。可达 UTC 瞬间须在 1901–2099 年内。

`windows[].candidate_id` 回指四柱及其独立解读核心。按 `dayun_age_comparison.segments[].birth_witnesses[].scenario_id` 将原折月窗配回四柱。出生节气与折月取整分别切分，同一四柱仍可能对应不同起运年龄。见证只是可达样本，出生分钟仍未知。这个入口给出原引擎的折月候选，交运公历日期的精度另核。紫微按[时辰复盘入口](ziwei-life-reading.md#只确认民用日期和时辰)核离散盘。出生时区和经纬度也已确认时，七政可按[时辰采样入口](qizheng-time-sensitivity.md#只确认民用日期和时辰)核各段实际见证。

续算时按原民用输入复核候选四柱、共同柱、实际出生窗及折月见证。存档口径或摘要与复算冲突时，按原日期、时辰和时区重建。

读取保存的八字出生快照时，原输入和已存的时区来源必须相容。明确标为固定偏移却附地区时区来源，或地区名相互冲突时，先核实原出生时区再重建。旧档未记录该来源时，仍可按留存的原始输入及实际可达时窗复算。同一地区的 TZif 摘要变更时，仍核对实际出生瞬间和候选区间。

### 已知民用出生钟面区间

已确认同一公历民用生日内的钟面上下界时，传实际日期、起止和出生时区。起点包含，终点排除，`24:00` 仅用于终点。先核原记录的边界含义。以下为合成输入。

```sh
python3 scripts/bazi_scenario_reading.py --birth-date 1982-12-14 --start 12:58 --end 15:02 \
  --sex 男 --timezone Asia/Shanghai
```

已知固定偏移时可改用 `--utc-offset 8` 等实际值。程序保留实际可达的钟面与偏移，按时辰、23 时换日、实际节气及起运折月分别切段。用 `windows[].candidate_id` 核四柱，再按 `dayun_age_comparison.segments[].birth_witnesses` 取同一出生分段的大运表。窗口起点的见证用于复核该段的模型，出生瞬间与精确公历交运日仍待核。只知日期或已选太阳钟面时，按其各自入口核查。

需要紫微时，用相同出生日期、钟面上下界及出生时区执行[紫微区间候选入口](ziwei-life-reading.md#已知民用出生钟面区间)。先分别完成单盘分析。合参时，按 UTC 取八字 `windows[].start/end` 和紫微 `candidates[].civil_spans[].start_utc/end_exclusive_utc` 的非空交集。涉及大运时，再取对应八字折月出生段的交集，并保留该段见证。例如何时跨八字 23 时换日、紫微同一民用日期下的子时索引如何归属，都按各盘原值。两个入口的编号各自独立。共同判断须覆盖整段可达出生时间并通过各候选的前提和反证复审。

七政经纬度已确认时，可按同一原始日期、时区和区间做[实际见证采样](qizheng-time-sensitivity.md#已确认同日出生钟面区间)。每个见证对应一个物理瞬间。安命仍取该瞬间的北京时间，整体出生规则继续暂缓。

### 八字大运年龄

总控 JSON 的 `bazi.dayun_age_windows` 保存原起运折月模型下的年龄区间，八字 Python 接口 `pai_pan_bazi.compute()` 同样返回该字段。第一运起点为 `qiyun_years × 12 + qiyun_months`，后续每步加 120 个月。每行给原运序和干支，`start_months_inclusive` 包含起点，`end_months_exclusive` 排除终点。第一行若为“起运前”，只表示原模型的起运前小运。

`dayun_rows` 的整岁范围是旧展示索引。起运若为 7 岁 7 个月，第二运在原折月模型内约从 17 岁 7 个月开始，查询 17 岁 2 个月时应按折月窗选第一运。遇交运月、折月取整或出生时刻误差会影响判断时，实际比较相邻两运，分别保留方向和适用条件；缺足够信息时保留交运未定。只有时辰或时辰未知时，独立引擎的 `birth_time_is_reference` 表示采用参考时刻。

八字单盘和总控文本以岁月和月数显示同一个原折月年龄窗，并单列旧整岁索引。总控在有出生误差时标明中心时刻。已枚举的总控文本按出生折月段同时列出实际四柱见证和对应的完整运窗。

详批已核定所问折月年龄区间时，用 `bazi_scenario_reading.luck_windows_in_range(snapshot, start_months, end_months)`。两端为整数月，左含右不含。逐 `tables[]` 保留原出生见证、原运表及 `intersections` 中每段的实际交集、原运窗和来源；`outside_table` 列本次请求超出该原运表的范围。原表内的起运前行也在 `intersections`。不同见证对应的请求年龄范围有差异时，分别调用并只取各自对应的表。若原表未核，读取返回的 `coverage` 及仍可核的本命材料。此入口仅裁切已核月数，公历对应日期仍按实际出生时点和所用折月模型另核。

启用出生误差枚举时，`scenarios.dayun_age_comparison.segments` 逐段提供原引擎折月结果和相应 `age_windows`。按原物理出生瞬间切十二节及模型取整分界，保存每段 UTC 起止，`end_inclusive` 指明右端是否包含。范围内同样的四柱可能有多个起运年龄，遇立春也可能改变顺逆。按各段 `birth_witnesses[].scenario_id` 回指同一快照的四柱候选并比较所问年龄所处大运。民用和平太阳时使用已核的候选区间交集；真太阳时仅把实际重算见证与折月段配对，联合覆盖以 `natal_candidate_coverage` 为准。不得任意搭配四柱与起运。折月段对原引擎计算完整，精确公历交运日和天文误差仍需另证。

## IANA 历史时区与有界误差候选

可选 `--timezone Asia/Shanghai` 使用标准库 `zoneinfo`；与显式 `--utc-offset` 互斥。不提供时仍为固定 +08。IANA 模式要求 Python 3.9+ 及系统时区数据库（或已安装的官方 tzdata 包）；不自动联网安装。JSON 记录区域名、实际偏移、fold 和可读取 TZif 数据的 SHA-256。历史数据库会更新，不是本仓固定数据；相同代码和分析年不足以保证不同数据库版本的结果相同。解析结果不证明出生地点记录或历史记载本身正确。

- gap（跳时导致民用时间不存在）报错，不平移到另一个时刻。
- fold（民用时间重复）必须显式 `--fold 0` 较早或 `--fold 1` 较晚；普通时间不接受无效的 fold=1。
- 历史 UTC 偏移可能包含秒，七政总控通过独立 `birth_instant` 保留秒，不再丢弃实际瞬间；排盘日时钟面仍向下取整分钟。
- 新增 `--time-basis mean-solar`：UTC + 经度 × 4 分钟，不含均时差。civil、mean-solar、apparent-solar 三者分开记录；节气判断始终用真实瞬间。

`--uncertainty-minutes N` 单独使用仍只提示中心盘非唯一。加 `--enumerate-scenarios` 开启候选：

```
python3 scripts/build_chart.py --solar 1986-01-03 --hour 23:00 --sex 男 --lat 30 --lon 120 --timezone Asia/Shanghai --uncertainty-minutes 10 --enumerate-scenarios --analysis-year 2026 --format json
```

区间定义为**已明确解析中心瞬间前后实际经过的 UTC 时间**，不是钟表上两端各减加 N 分钟（DST 跨越时二者不同）。范围是闭区间，N 最大 120 分钟，完整 UTC 区间须在 1901–2099 年内。区间越出年份范围时，总控保留可计算的中心盘和原有误差警告，跳过受影响的候选枚举或七政敏感性比较，不截断区间；文本给出原因，JSON 对应结果为 `null`，原因记在 `degradation.scenarios` 或 `degradation.qizheng_sensitivity`。区间不是概率分布，不自动选最可能的候选。

仅比较四柱干支与紫微的公历日期、时辰索引、民用出生年份。civil/mean-solar 在模型内按午夜、各奇数整点、实际节气与时区偏移跳变划分，输出实际可达见证时刻和区间，以及该有限字段集合的 stable_fields/changing_fields。时区跳变逐个整数 UTC 秒检查（TZif 的转换时间是整数秒）；不靠粗粒度抽样推断无变化。端点包含；中间子区间右端不包含。只合并完全相同字段的可达候选，不做四柱逐项笛卡尔积。

apparent-solar 采用随瞬间重算的原均时差公式，对钟面边界数值二分包围至不超过 1 毫秒，计算包围两端的实际候选。**该模式未证明完整覆盖**，coverage 为 numerical_witnesses_not_exhaustive；stable_fields 始终为空，observed_constant_fields 只表示已计算样本未变化，不能当作稳定。不给这些候选附精确生效区间。1 毫秒仅为数值求根容忍，不是均时差模型或节气的天文精度。边界可非常接近，不以无变化样本排除未解析的短区间。

明确传入 `--dut1-seconds` 时，中心盘、真太阳时枚举及续算使用同一个原值。存档未在原输入保存此值时，可用已保存的七政地平合同取值。两处均未记录的旧枚举可按原来的 0 近似复核。若留存候选钟面与原参数重算不符，按原出生输入重建枚举后再续算。

顶层 `scenarios.scope`、`excluded` 和 `stable_fields` 描述离散四柱与紫微候选，起运另查同级折月面板。连续七政天体位置、完整紫微排布、不同晚子时学派和天文模型误差仍按各自范围核查。八字 23:00 换日、紫微午夜公历日期及其原子时索引保留，不擅自统一。节气近边界告警仍需权威历表复核。1901–2099 只是枚举工程范围。

总控 JSON 在显式枚举非零误差时，另用这些离散输入重排[紫微阶段与本命关系的候选盘](stage-and-spouse-models.md#紫微大限与本命关系)。该候选面板沿用枚举器的覆盖标记，保持原民用出生年与分析年。续算各候选年/月时，按[生活领域面板接口](ziwei-life-reading.md)传入同一快照的候选 ID 和独立查询点。完整紫微、天文误差和人生判断的覆盖范围仍须分别查证。
