# 七政规则版本与有条件解释 v1

这是项目原创的实现说明，不是新发现的古籍定本，也不验证命理预测。只描述规则输入、关系和反例，不导入外部源码或古籍全文。本文适用项目 MIT；既有七政数字转录的版权与底本尚未核清，本文不替它们重新授权。

## QZ01：命度宿主为我

规则版本 `qizheng-degree-relations-v1` 固定采用命度宿主五行，日宿折火、月宿折水。对另一曜五行：生我为恩、我生为用、克我为难、我克为仇、同我为同。曜五行来自引擎的十一曜固定映射，不是该曜当前所躔宿的宿主五行。例如金星躔角宿，星仍属金，角宿主木；不能把金星改成木。

若命度牛宿（宿主金），土及计都为恩、水/月/月孛为用、日/火/罗睺为难、木/紫气为仇、金为同。条件是采用本引擎的宿界与度主法；换宫主为我、改变宿界或出生时间后，必须重算而不能照抄。这仅回答传统规则怎样分类，不证明有人相助、事业成功或疾病发生。

## QZ02：宫支、宫主、宫主五行分开

本项目以既有 `references/qizheng/states-tables.md` 第一节的本地整理说明为待校勘依据，使用子丑土、寅亥木、卯戌火、辰酉金、巳申水、午日、未月的宫主表。日主折火、月主折水。此为传统宫主映射，非现代黄道星座的天文事实。

例如卯支五行木，但本表卯宫主火；若度主金，火克金为难。若误拿卯支木来算，将错误得到金克木为仇。午宫主日和火同属火但星名不同；未支属土而未宫主月折水。输出须保留这三个概念，不能只给一个模糊“宫五行”。宫主与度主单一生克关系不能独自证明宫度相得、庙旺、成格或吉凶。

## QZ03：物理量与传统口径不能合为一项

日月五星是天体；罗睺与计都是此实现的月球平交点及对点；月孛是平远地点；紫气是约定锚点的虚拟循环。后四者不是四颗观测行星。平交点/真交点、平远地点/真远地点、计都交点/远地点以及紫气锚点不是可互换别名。

`calculation_profile` 描述计算版本，规则 profile 描述传统映射。前者修正不会自动验证后者。角宿一赤经不能当黄经；从回归黄经减某个常数不等于复原古代赤道宿度。近似黄经分区可作已声明模型的演算，不能称为精密古宿界。宿内度数没有经过专门校核，不支持分度庙旺或应期。同样，传统立命宫使用北京时间时辰不等于物理东方升点，也不等于真太阳时立命。

## QZ04：检索和停用边界

`qizheng_rule_profiles.analyze` 只接受明确 `legacy-v1` 或 `physical-v2` 计算版本，并检查宿主及恩用分组内部一致性。旧盘未写版本时不会自行冒认。未知规则版本、缺升点、命度靠近宿界、原点超出已核验范围或时间存在未展开的不确定性时停止命度解释；太阳靠近宿宫界时单独停止宫主关系解释。传入受支持版本只是输入契约，不是数字真伪认证；调用方必须传确定性引擎输出，不得给外部盘随意贴标签。

仍可说明 QZ01/QZ02 这样的条件推演，但不启用庙旺歌、格局库整章，更不以旧文件标题宣称“原典全文已核”。参考文件的本地 hash 是防变更线索，不是古籍真实性或许可证明。knowledge catalog 新增的只有本文原创释义；旧资料未获个人 ledger 新授权。恩用角色表可能在不同实现中颠倒或采用其他“我”，比较时须逐项列出基准、五行表及生克方向，不能因同名就融合。

## 使用与可复核例

```python
import pai_pan_qizheng as qz
from qizheng_rule_profiles import analyze, format_reading
chart, warnings = qz.compute((1990, 1, 1), 12, 0, 39.9, 116.4)
# 新引擎自行写 calculation_profile；旧快照只能在已核实来源后标 legacy-v1。
print(format_reading(analyze(chart)))
```

测试内牛宿/卯宫的样例是明确的合成结构示范，不伪称某人的实际排盘。实际场景须使用整套引擎结果，并保留地点、时区、计算版本与时间误差。输出既列条件、反例和具体关系，也保留未验证标签，不用空泛免责声明替代实质解释。

## 独立优化的素材迁移清单

七政不沿用八字强弱或紫微庙旺模型。它需要自己的物理计算、传统口径、知识适用条件和比对样本四条验证链；前三者的完整并不等于预测有效。

| 本地素材 | 可以迁移的内容 | 当前不能直接迁移的内容 | 仍缺的复核 |
| --- | --- | --- | --- |
| `scripts/pai_pan_qizheng.py` 命宫、恩用函数 | 明确的输入/输出与旧版回归样例 | 旧黄金值作为真实天文精度证明 | 独立星历、边界样本、同瞬间时区变形测试 |
| `references/qizheng/states-tables.md` 第一节 | 三种宫五行概念的区分、QZ02所用本地宫主映射 | 整篇庙旺歌、宿内分度和富贵结论自动启用 | 原版影像与章节定位；逐条宫表与关系律冲突处理 |
| `references/qizheng/classics.md` 宫度主及恩用讨论 | 学派问题清单、度主/宫主/身主的不同职责 | 仅凭“原典”标题认证古籍引文；把不同“我”融合 | 底本、版本谱系及逐条反例；身主计算口径 |
| `references/qizheng/palaces.md` 十二宫材料 | 传统宫位意义与宫主计算分层 | 未计算身宫、十二宫守照即推婚病财事实 | 十二宫轮转方向、宫主映射和物理宫界分别比对 |
| `references/qizheng/stars.md` 逐曜材料 | 提取候选规则的前提清单，如昼夜、四时、会合 | 把曜五行与宿五行混写，逐曜歌诀当无条件断语 | 一条规则一个来源定位、条件、排除与替代解释 |
| `references/qizheng/forms-geju.md` 格局材料 | 格局定义和破格条件作为待研究对象 | 星名齐全即成格、古文称贵即预测显贵 | 同名异义、角距阈值、会照框架和反例数据 |

上述原始文件只作待核素材，来源仍是其本地数字整理声明，未完成外部书目和许可验证，不因列入清单就获准整篇引用或移植。新增加的机器可用规则只有 QZ01/QZ02，不暗中启用后三个材料库。

引擎文件头提到的 stem-branch、guolaoxing 与公开紫气实现目前只提供比较线索。此模块没有新核实这些项目的固定提交、许可证或算法正确性，没有复制其代码，也不将其数值升格成独立黄金基准。后续若迁移，应先固定版本和许可，明确比较的是黄经、赤经、真/平交点还是约定紫气，再比较同一物理量；不应为了对齐一个应用而反推篡改物理结果。

优先补齐次序：独立日月五星/升点星历样本 → 宿界所用赤道或黄道坐标与历元 → 逐条校核宫主/度主关系 → 昼夜四时等附加条件 → 具备完整前提后才考虑升殿或格局。每一步保存“不适用/未知”反例。任何阶段都不由软件一致性推论命理准确率。
