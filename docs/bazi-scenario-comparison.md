# 出生时刻候选的结构对照

`build_chart.py --enumerate-scenarios` 在原枚举结果上附加
`bazi_scenario_comparison`，不改变四柱、区间、默认时间口径或中心盘。
不开启枚举时该字段为 null，原输出仍是中心盘。

每个可达候选以原 `fields` 四柱为输入，按八字引擎重建藏干与十神，
独立执行 `bazi_core_reading.analyze`。JSON 保留完整结构结果、规则版本、
来源 hash、UTC 见证、排盘钟面和原区间。文本只呈列一次共同证据，
再对每个候选呈列变化项，避免反复复制全套免责声明。

对照项目包括日主、月令季节、同五行根气、冲合刑害配对、月支藏干透出、
生扶与克泄耗线索；结构分析提供格局条件判断时也纳入比较。
日主跨界后所有十神和根气按新的日干重算；跨节气后月令判断不共用中心盘。
候选差异表示输入不确定性，不表示未来结果概率，也不为候选分配可信度。

civil / mean-solar 的共同证据仅在枚举器模型覆盖范围内成立，
不覆盖天文误差、其他晚子口径、起运、完整紫微或七政。
apparent-solar 的共同项只记为 observed_constant_evidence，
stable_evidence 永远为空，不把有限数值见证称为穷尽证明。

## 合成验证

`python3 -m unittest discover -s tests -p test_bazi_scenario_reading.py -v`
覆盖 23:00 换日、2026 立春、嵌套误差区间、纽约 DST gap/fold、
真太阳时非穷尽标记、JSON 与文本一致。

实际 CLI 对拍采用合成输入 2005-12-24 23:00 和 2026-02-04 04:02，
男、纬度 30、经度 120、civil、±10 分钟、分析年 2026，分别输出 JSON/text。
这些检查验证实现的一致性，不是天文外部金标准或预测准确率证明。

候选对照的独立文本输出也附格局候选来源署名、固定版本、释义行号、
贡献历史、改编说明及 CC BY-SA 4.0 链接，明确许可适用于上述对照中的
格局候选解释，不依赖随后中心盘的署名。相同完整来源元数据仅呈列一次；
不同来源或改编说明分别保留。JSON 的完整来源元数据不因文本渲染而改变。
