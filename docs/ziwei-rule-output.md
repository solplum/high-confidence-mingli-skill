# 紫微规则输出边界

紫微 CLI 和 `build_chart.py` 默认输出排盘事实及**本实现的组合匹配**，不再把上游格局叙述直接当作个人判断打印。十二宫、星曜、原始亮度、四化和大限算法没有修改。`vendor/`、上游版权及来源文件保持原样。

## 使用

旧命令与默认文本格式仍可使用；`--shichen`、`--hour` 和 `--format json` 不变。两入口新增 `--explain-rules`，展开规则条件的读法和实现限制，不启用预测。例如：

```
python3 scripts/build_chart.py --solar 1998-06-30 --hour 23:00 --sex 男 --lat 23.13 --lon 113.26 --analysis-year 2026 --explain-rules
cd scripts/pai_pan_ziwei
node --import tsx pai_pan.ts --solar 1975-12-11 --hour 06:30 --sex 女 --age-year 2026 --format json --explain-rules
```

JSON 保留 `schema_version: 1` 及既有字段，新增 `rule_output`。文本与 JSON 使用同一个适配器 `rule_output.ts`，既有 `chart` 数据不受解释选项影响。

## 读法与依据

- `patterns[].name` 是旧识别器的组合名，`level` 是旧代码分类；它们不是现实吉凶、风险概率或准确率。
- `conditions.required`、`bonus`、`breaking` 保留已命中的条件结构和条数。文本称后两项为“附加条件”和“限制条件”，不称“加分”或“预警”。有事实意义的括号内容（例如缺少哪颗星）仍保留。
- 适配器逐条改写条件中混入的个人预测，还把旧 `dim` 明确解释成“不或陷”，不把它误称为精确“落陷”。某些旧检测只按星名而非四化字段查找，此处如实标记，未悄悄修正算法。
- `description` 现在复述实现条件，不携带上游断语。命宫小结只列真实主星，空宫借星另见原始宫位数据，不输出未经核验的人格画像。
- `source` 指向可追溯的代码；`source_status` 明示这是实现出处，非已逐条核验的古籍引文。未核验的书名、章节与预测性叙述留在上游代码中，不冒充一手证据。
- `--explain-rules` 逐条列出本组合所涉星曜的实际宫位、原始亮度、本命四化、三方四正内外关系及 `chart.palaces[i].stars[j]` 数据路径；并列命宫全部实际主星、已触发附加/限制分支和范围核对提示，便于发现部分组合缺星或未排除其他同宫主星的情况。随后解释条件分支、合并亮度和实现边界。进一步传统解读需按知识库来源登记另查具体原文，不能靠打开此选项恢复自动健康/事故/财务断语。

## 验证边界

回归包含评测暴露的 1998-06-30 子时与 1975-12-11 卯时、1961-01-21 子时女紫微破军同宫反例、480 个日期/时辰/性别组合、两种格式与解释开关、总控和旧 CLI。检查组合名称、分类和条件无丢失、`chart` 未被修改及无旧个人预测叙述。它只验证输出治理和兼容性，不验证命理预测能力，也不宣称旧格局识别算法已经全面校正。
