# 四宫联读 v1

默认在紫微 text 与 JSON `rule_output.domain_reading` 输出。不需要 `--explain-rules`。原始引擎与旧条件匹配不变。

这是有限的现代资料主题解释，不是已验证的人格或预测模型。14颗主星各只启用一个主题和一项反证问题，按命、财、官、迁实际位置区分讨论对象。两个主题组只在所需三颗星都出现在四宫内时作条件推演；缺星 withheld。它们是项目综合，不是古典格局定义，也不赋予得分或吉凶等级。

读取范围：`knowledge/catalog.json` 中 `ziwei-domain-conditional` 的16条项目释义。依据固定 iztro-docs 版本的 major-star、palace、star 局部段落，保留其MIT署名，不引入八字CC BY-SA资料，也不启用古籍数字录文、pattern正文或四化断语。新增记录中的具体行号为人工核读范围，不把同节性别、经历、疾病、财富等断语带入。

亮度只取 `brightnessRaw`：庙/旺讨论主动表达，不/陷讨论保留表达，得、利、平不进一步强分；缺失不当作平。这是该现代说明的约定，不改引擎表，也不当作成败强弱。四化仅显示本命事实，不读取宫干自化或运限解释。空宫不当成本宫实坐借星，当前有限版本暂缓星性结论。

每宫都附实际星位坐标、出处、反证问题、未满足条件；关系部分说明不同领域不能互相充当现实证据。现实做法与主题相反就应撤回，而不是补造隐性性格。辅煞、完整组合和现实背景尚缺，不能宣称完成整盘详批。

来源检查首次在每个Node进程运行本地Python validate，失败或Python缺失时整个新层withheld，旧引擎继续输出。检查成功在进程内缓存；批量过程中若更新资料，应启动新进程。检查只证明登记完整性，不证明语义或效果。新增层不产生可直接视为 supported 的ledger claim，若接入ledger仍须另按其契约核对。

演示与前版对照见 `examples/ziwei-domain/README.md`，测试见 `tests/test_ziwei_domain_reading.py`。这些测试仅验证分支、数据一致性和来源边界。
