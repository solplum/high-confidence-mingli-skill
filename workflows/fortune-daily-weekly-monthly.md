# Fortune-Daily-Weekly-Monthly — 运势查询 Workflow

> **知识来源门（所有引用必读）**：先读 `knowledge/README.md` 并验证 `knowledge/catalog.json`。这条约束优先于下文旧的“原典/权威/书名章节”说法；旧摘要仅作有来源的现代整理，隔离条目不用于解读，未核版本不作逐字古籍引用。直接读旧 references 也必须过此门。


> 由 SKILL.md §0 路由触发。处理今日/本周/本月/今年/指定月运势查询。
> 输入: query_type, query_date, domain(可选)
> 数据: `~/.claude/fortune-telling/chart.md` + `~/.claude/fortune-telling/memory.md`

## Phase 1: 加载

输入:
- `query_type`: 今日|本周|本月|今年|指定月|回顾
- `query_date`: 查询日期 (YYYY-MM-DD)
- `domain`: 可选，感情|事业|财运|健康
- 运行时画像: 从 memory.md 读取 (认知模式+情绪底色+核心矛盾+当前关注+已验证解释偏移)

执行:
1. **引擎优先**：环境有 python3 → 跑 `scripts/pai_pan_bazi.py --solar <查询日> --sex <性别>`，流年/流月/流日干支一律取脚本输出（无年份范围限制），跳过下面第 2-4 步口算
2. （无 python3 降级）确定流年干支: 查 SKILL.md §6 预计算表，以立春为界
3. （降级）推算流月干支: 用 §7 年上起月法，以节气日期为界
4. （降级）推算流日干支: 用 §7 日干支推算规则（主锚点 **2026-01-01 = 乙亥日，0-based 序号 11**；公式 `(11 + 天数差) % 60`）
   - ⚠️ 历史 bug 教训：旧版曾误写锚点为「2026-01-01 = 乙巳日」，导致全日干支错位。**每次降级口算后必须用验证锚点 2026-01-31 = 乙巳日（序号 41）自检**，并在输出中标注「口算降级」
5. 查流年四化: 用 §7 年干四化表（或紫微引擎 `--age-year` 输出）
6. 计算关键冲合: 原局冲合 + 流年冲合
7. 边界检查:
   - 降级路径查询 2036+ → 标注「预计算表外，置信度降一级」（引擎无此限制）
   - 节气边界当日 → 以 0 点是否已过该节气为准
   - 大运切换年 → 同时列出两运特征
   - 无法确定日期 → 返回「请问您想查询哪一天的运势？」

输出: { year_ganZhi, month_ganZhi, day_ganZhi, year_siHua, key_chongHe, current_daYun, boundary_notes }

## Phase 2: 并行典籍式解读（SKILL.md §9.5 段一）

有子 agent 工具时 parallel（无则顺序内联执行，schema 不变）。缺盘时跳过对应盘并记录。
**每盘按其体系框架解读，先查对应 references，论断挂典籍出处**：

- **八字**: 按日主→十神→神煞→五行喜忌→大运→流年骨架解读该时段
  - 输入: 原局八字(chart.md) + 流年/流月/流日干支 + 冲合
  - 知识源: `references/bazi/classical-texts.md` + `wuxing-tables.md` + `shensha-table.md` + `dayun-rules.md`
  - 重点: 日主与流年流月的关系、原局核心冲合是否被引动、印星/用神状态
  - schema: `{ assertions: [{ statement: string, citation: string, domain: string, direction: "顺行"|"张力"|"中性" }] }`（citation=典籍名·章节）

- **紫微**（有数据时）: 按命宫→十二宫→四化→大限→格局骨架解读该时段
  - 输入: 原局紫微(chart.md) + 流年命宫（**标准口径：流年地支所在宫**） + 四化飞星
  - 知识源: `references/ziwei/classics.md` + `patterns.md` + `sihua-tables.md`
  - 重点: 流年命宫、生年四化与流年四化的交互；格局只讲脚本命中的，破格如实打折
  - schema: 同上

- **七政**（有数据时）: 按度主→恩用难仇→昼夜取重→立命宫骨架解读该时段
  - 输入: 原局七政(chart.md) + 当前大运五行 + 时代运五行
  - 知识源: `references/qizheng/reading.md`
  - 重点: 命度状态、难仇恩用关系；有资料与字段支持的宫表级状态可查表，未考证的宿内分度不判。原局不能冒充当期七政运限，时代运不作补克证据
  - schema: 同上

## Phase 3: 跨盘对照 + 分层解释（§9.5 段二）

单线执行:

1. **跨盘对照**: 按 §10 核查领域与时间、条件与方向、共同依赖；列一致 / 冲突 / 范围不同 / 信息不足。
   单盘出处与盘面支持可追溯性，不证明预测能力；缺盘只说明缺口，不升降可靠度。
2. **分层解释**: 按 §8 选择问题相关且条件完整的层次；缺失层不补造，不作百分比合成。
3. **领域筛选**（信号映射见 `references/domain-signals.md`）:
   - 用户指定领域 → 主展开该领域，其他收缩为一句
   - 未指定 → 优先展开当前时段最活跃的领域
   - 感情和事业同时活跃 → 优先事业
4. **核心张力提取**: 找出最主要的能量 assertion + 斯多葛视角

## Phase 4: 斯多葛收束（§9.5 段三）

**引用密度（轻引用管线）**: 每篇主判断挂 1-2 条最贴典籍依据，格式固定两行：
`> 依据：<典籍名·章节>「原文」` + 转写后的斯多葛表述（引文原样，断语转写）。

**禁用词替换**: 吉/凶/好/坏 → 能量状态描述; 你应该 → 你可以选择; 注意/小心 → 值得留意

**查询深度映射**:
| 查询类型 | 命格展开 | 流年 | 流月 | 流日 |
|---------|---------|------|------|------|
| 今日 | 一句 | 一句 | 概要 | 纹理 |
| 本周 | 一句 | 一句 | 概要 | 日柱走势 |
| 本月 | 一段(3-4句) | 简述 | 详解 | — |
| 今年 | 完整展开 | 详解 | 详解 | — |

**输出模板**:
```
## [查询类型]运势

### 背景
[命格定调，长度按查询深度缩放]

### [时间]能量
[流月/流日干支 + 关键冲合 + 多盘信号 + 条件、冲突与缺口]

### 核心张力
[最主要能量 assertion + 斯多葛视角]

> 依据：<典籍名·章节>「原文」（轻引用管线 1-2 条）

> 🏛 你可以把握的是：[具体到当前能量状态的最小动作]
```

## 约束

- 回顾模式: 同查询逻辑 + 标注「回顾模式——只分析，不预测」
- 模糊查询("最近"): 默认展开到流月
- 意图识别("今天适合做X吗"): 映射到最匹配深度 + 针对性回答
- 用户沉默不反馈 → 不做推断，跳过校准
