# Fortune-Daily-Weekly-Monthly — 运势查询 Workflow

处理今日、本周、本月、今年、指定时段及回顾查询。先读取 `workflows/fortune-auditable-reading.md`，执行固定输入、覆盖计划、单盘证据、独立反审、对照与交付的共同流程；查询时段短不降低核查深度。解释与裁决遵循 [解释标准 v3](../docs/interpretation-standard.md)，知识检索遵循 `knowledge/README.md`。

输入：`query_type`、查询时间区间及民用时区、可选领域与目标、已有命盘与本次引擎快照，以及有来源的性格、偏好与现实背景。出生时间口径与查询时段分别记录；个人背景可影响策略适配、体感和行为成本，不提供缺失的当期证据。

## Phase 1：固定时间范围并检查边界

1. 将“今天/本周/今年”等解析成用户所指时区内的明确区间。模糊“最近”可先按当前民用月并说明采用范围；用户已有具体范围时沿用。无法确定且会改变判断的日期或时区才补问。
2. 按 `docs/time-contract.md` 和现有脚本 `--help` 选择实际所需的日期、时刻、偏移及分析年，保存命令和原始输出。目标年用于分析，不改变出生瞬间；查询日排出的四柱也不是用户的出生盘。不得用一个默认时刻代替整个查询区间。
3. 检查该区间内可能改变所用字段的实际节气瞬间、换日规则和运段切换。仅当相关字段在已检查区间中没有跨界时才用单一值；有变化则分段或列候选。边界无法检查时标明范围和缺口，不以零点代替节气实际发生时刻。
4. 本体系有可核对输出及适用规则时才使用当期宫位、四化或其他动态字段，注明口径与时间层；不由手工表自行安星或混入宫干飞化、自化。
5. 无 Python 环境时，仅按 SKILL 的离线降级说明保留可核对信息，标明未运行引擎。近似节气日期不足以确定边界内单值；无法生成的候选和衍生字段暂缺，不把降级记录称为完整机器核查。

将区间、实际采样/分段、边界、可用字段和未覆盖范围写入工作记录。连续七政位置、完整运限或其他未实现的能力不能因分析时间充裕而视为已检查。

用户问「今天剩下」「今月余下」或明确只问从现在起时，以用户所指的当地实际时刻为起点，以所问日或月的结束为终点，按这个子区间核查。追问从整段改问余下时，先给余下的方向，之前的分段结论可按需用于回顾。单纯提供当前钟点而仍问整日或整月时，保留整段。安排只能用实际尚可用的时窗。

追问换时区时，先核是同一时段只换显示、同一时段改用另一地的查询民用钟面，还是任务真的改期。只换显示时，保留原查询口径与实际时段。改查询时区时，把同一 UTC 起止换算到新时区，复核日柱、农历月日与公历阶段，节气仍按同一物理瞬间。按新地点的相同钟点重排预约或例行任务时，先核新的实际起止，再检查原约定、当地休息和查询边界。整日和整月各按用户所指的当地日期范围另核。

八字按民用查询钟面分析时，用 [查询时段事实入口](../docs/time-contract.md#八字查询时段事实)完整分段。查询地的 IANA 时区已知时，传入 `--timezone` 处理实际偏移变化。取用户所问的年、月或日层，按各段起止核已确认的大运和适用规则。查询跨原出生范围时，另按已核出生后段重建个人分析计划，保留原请求中暂无法判读的时段。十一月辛续算即使缺大运表，也按原民用出生时刻核这条边界。返回 `birth_time_unverified` 或 `birth_core_unverified` 时，该段只供内部查核，待补齐相应原资料再给个人方向。

紫微按[实际区间入口](../docs/ziwei-dynamic-facts.md#晚子时和区间覆盖)生成带偏移计划。对每个已核出生候选，先用 `audit_query_windows` 配空面板取得实际可读段，再按返回的查询点运行适配器与[生活领域面板](../docs/ziwei-life-reading.md)。跨出生边界以重新切出的出生后段为准。区间审计给出 `requires_civil_clock: true` 时，按动态事实说明绑定 `probe.civil_time`。出生先后未核的时段只保留历法事实。判断依赖旧当前大限时，用该段 `stage_year` 独立指定 `--analysis-year`。汇总前用同一原计划复审实际点面板，记录漏读段和未核的大限年。八字节气月与紫微农历月的换月时刻分别记录。

区间跨紫微动态工程范围时，按[部分覆盖办法](../docs/ziwei-dynamic-facts.md#跨动态历法覆盖边界)读取可用的动态子区间，记录超出范围的时段，并按原问题独立核对应的大限。

要求逐个比较公历月时，先为每个所问月固定民用起止，再分别核对其中的八字节令段与紫微农历段。一个历法段跨公历月时，各月各报它实际覆盖的部分。

查本周、连续数日，或比较和选择某月内的具体日期时，用 `--layer day` 取得实际换日段与上层事实。所问目标有已批准的日层依据时逐段核对，再把同方向的相邻时段合并说明。若只能判月层，把结果写成月度背景，并明示日级方向缺口。

如果回答涉及紫微日层事实，使用 `ziwei_query_windows.py --layer day` 核实际民用日期与晚子时分段。逐段运行点适配器，区分已准入日层事实和晚子时暂缓段。日层只用于盘面事实核对。只读年／月背景时使用相应年／月入口。

## Phase 2：沿相关时间层深入单盘

实际采用 [综合判读方法v1](../docs/conditional-judgment.md)。八字先冻结本题所需的原局/运段假说与方向判据，再按BJ07–BJ08比较所问年/月/日相对该背景新增的支持、制约与成本；单时段无需强制另选日期作对照。给首选的依据、反向条件和对分支的敏感性，保留作者外推身份。紫微按新独立春节/农历月profile实际分段，原公历年龄大限继续保留；只有获准的年/月卡承担主题解释，日层事实不能替代日级效力规则。

完整条件模型按 [M0](../docs/model-judgment.md)执行：先检查整个所问区间内的必要条件与特指反条，再给有已批准时间适配依据的模型结果，并报异读和未决交互。子月辛金用[八字 QX 查询分段入口](../docs/bazi-qiong-xin-zi.md#运年月日的分层适配)同时传历法分段、已核折月年龄，以及独立确认的本次查询窗口与时间层。丑月 BZ-QXC01 和寅月 BZ-QJY01 仅作所问专业发展的本命背景。追问改期或从月改问日时，使用新请求的窗口和时间层重新核验。已知大运边界落在历法段内时再分段，分别判断。

改期跨公历年时，用新备选的直接依据重新给首选。按实际切点说明公历阶段、节令、农历年月及日层各自哪些已变、哪些仍延续，并点出实际改变排序的那一层。整月同向时仍逐段核它的依据。现实安排照本次确认的权限、时段与约定核对。

逐段对照上一层和本层的模型结果。方向相同时，给出本段复核后成立的条件方向，标明它从哪层沿用，并单独说明当期新增作用是否可判。只有新增作用未决时，将未决限定在该作用。方向变化时，说明是新增正支、原正支退出还是触发已核反条，分别给出各段结果。换日撤下日层反条时，标明换日切点，并复核流月、大运等上层是否仍有同一限制。若限制持续，写清它来自哪一层及已核的退出点。两套历法切点不同时，各自标明改变了哪项判断。若一个切点只减轻某项条件性成本，只对实际受该成本影响的目标推荐切点后的时段。

同问整个民用日和其中的办事窗口时，按各自范围给判断。即使只在下午择时，整日问法仍须交代 23:00 后的实际日段及其可判方向或具体缺口。人工判读也按完整历法计划逐段核对。换月使一项相关解释退出时，交代同一目标上仍成立的上层依据，以及是否有相关的新增条件。

同时问整月和两个具体时段时，即使两个时段都在同一大运，也要交代整月内已核的交运切点和切点两侧与所问目标相关的条件。

追问更正出生分钟时，即使四柱与折月大运表相同，也按当前出生瞬间重新核实所问范围内的折月年龄和实际交运切点。按新证据重跑并说明哪些时段的判断改变。旧的精确续算若依赖已知折月年龄却没有绑定原出生瞬间，先重新续算。

归纳完整日、月或自定时段前，用 `audit_query_range` 核原查询的完整历法计划、实际已读窗口及本次原出生快照。另把本次独立确认的起止、时间层、时区和适用的 fold 传入 `expected_request`，按 `unread_windows` 写清尚未读的时段。首次续算及重用旧面板都把本次独立核实的 `verified_folded_ages` 传入，逐窗口和见证核对折月年龄。历法无漏段并不足以证明大运证据已核，另看 `folded_age_evidence_checked`、各窗的年龄及 `luck_status`。比较同一个人的时段变化时，查 `unread_by_birth`，按同一出生候选对照，不能把换盘误当成换时段。八字续算按 `witness_coverage` 区分已读见证和同档未读见证。只问原快照中一条已独立限定的见证时，续算和覆盖审计均传入同一 `expected_birth_witness`，按该见证交付。归纳多个出生候选时，先查所问范围内其余见证及各自折月窗。年龄未核的见证仍保留已核盘面与日期事实，并标明相应方向缺口。六字快照或已枚举但缺折月表的存档，另按 `natal_candidate_coverage` 核各本命候选是否已读，记录实际出生范围或已核数值见证。六字时柱仍未知，缺表时大运仍未知。

先按问题建立覆盖计划，再独立分析各可用体系：

- **八字**：区分原局背景、实际运段和查询期字段，说明当前解释如何依赖原局条件。旺衰、调候、格局和喜忌分别核对，不能凭一个冲合或五行数量定当期事件。
- **紫微**：分开本命宫、已核大限、准入流年和流月。劳逸分别查疾厄的身体管理与福德的收束主题。换月撤回某项月度解释后，仍核同一目标上已准入的年度分量。流日只作事实核对。
- **七政**：使用现有度主法输出；明确选择乾元宫主参照时保留受限结构面板。当前没有七政月限/小限及相应应期能力，原局结构不能冒充当期运限，八字大运或时代运也不作为七政补克证据。

按知识来源门查询实际登记释义，记录检索及无匹配结果。每个主要主题须核对具体字段、适用条件、反向信号、替代解释和相关边界，形成 ledger 或受限面板的对应记录。没有支持日事件的规则时，可以详解现有结构及它为何不足以支持当日预测。

在同一时间、领域、目标和评价对象内比较支持与牵制：哪些条件决定主要方向，哪些只是成本，哪些足以翻转。可依合法资料与实际关系作作者定性综合，不要求程序已有吉凶分数；不能凭生助、克冲或化禄直接定好坏，也不以盘数、星数或五行数量抵消。先冻结结构判断，再结合有来源的个人背景解释目标适配与体感；未知偏好保留分支，不写成已测人格。

## Phase 3：独立反审与有界对照

按共同流程完成反审，保存发现及撤回、降级或修订的处理记录，再按同一领域、时间范围和相容场景对照单盘结论。

逐项核对原问明确提出的总体评价与各个领域。只问指定领域时，其他领域在影响该判断时展开。询问总体时，按有数据与规则支持的领域核对覆盖、主次依据及足以改变总评的缺口。领域的优先级须有本题依据。

先核用户所说的「整体」指什么。若明确问获准模型内的整体配置，完整条件已核时直接给该模型内的方向。若问生活各方面的总体，按实际覆盖和主次另作归纳。实际取舍按用户的目标优先级、时间与授权判断，任务可行性不能补作整体运势。同一评价轴的正支成立、退出或受限发生变化时，写出各段方向与实际切点。单一总标签需要能解释整段主次的依据。

跨盘共享输入和来源继续记录，缺盘不转移给其他体系。无法与查询时间层对应的判断列“范围不同”或“信息不足”，不用长期描述填满每一天。

## Phase 4：分层交付

按[共同交付流程](fortune-auditable-reading.md#5-分层交付结论主题详析证据附录)在前两段给查询区间与顺阻倾向。同问长期和具体择时时，也在前两段直接给所选日期或明确的排序缺口。并问总体和领域时，在开头分别回应各项。总体有足够依据时直接给方向并说明主次；仅部分领域或时段可判时，先说具体对象、窗口及偏顺或偏阻，在开头同时交代总体和其余所问项的决定性缺口。若只能凭已确认的分工、时限等现实条件判断可推进，开头就写明该依据，并同时交代传统时段方向是否能判。只有体感或条件主题可答时，写清其具体范围。平稳也需要实际支持。

正文按原问组织。同问今日与今月整体时，先逐项给方向或缺口，再围绕本次真正影响判断的领域和目标展开。只问总体时，无需列齐领域榜单，也不默认以学习或工作代替其他领域。缺方向依据与缺具体事件依据分别说明；若全部所问方向确实未决，集中简短交代决定性缺口与实际可答范围，不把本命术语、限制或内部核查过程扩写成完整日/月运势。

大运等必要条件未核时，若已看到与原问目标有关的特指反条事实，仍交代它出现的实际分段及对该目标须复核的限制。保留完整模型的未决状态，其余时段和领域各按已核证据回答。

旧档缺项时，先用已独立确认的原输入和现有入口重建可核证据，再决定是否还需补资料。原表确实不可用或所问时期越过表尾时，明示哪一层方向待核，同时交付已核本命、实际时段事实及仍有依据的独立领域判断。若现实硬条件改变首选，分别说明当前可执行选项与该时窗已有的传统方向。

若用户要在几个时窗内推进同一件事，先分别给出各窗对同一目标的判断，再说明现有依据支持哪种取舍。完整模型中因正支条件不符而撤评，与因特指反条而判受限，分别写出。多个时窗得到同一方向时，说明还有哪些条件能区分它们。缺少这样的依据时，保留相同方向并说明无法进一步排序。

任务须连续完成且可用窗跨界时，核用户要求的最短时长能否完整落在切点前或后。只能跨界完成时，交代会经历哪些已核条件和何时变化，再按现实约束给首选。整项任务的净方向须另有依据。

两窗只因跨月出现不同的条件主题时，先找两边是否都可能触及同一个瓶颈。例如一侧增加配合投入，另一侧增加职责安排，两者都可能挤掉表达需求的时间。只有本题有依据说明哪一侧的代价更相关时才按这项成本给首选；比较来自月层时，直接标明比较的是月度背景。

追问只取消一个原时窗时，按剩余时窗重选，并标明原比较各自适用的起止。新增、挪动或缩短钟面时窗时，按新的实际起止核对时段事实和可行性，即使公历日期相同也要检查是否跨过换日、节气或交运。先答新时窗的方向和能否执行。追问改了目标时，先按新目标给出现实可行的选择及所问时段的判断。提到仍成立的旧方向时，在同一句写明它对应的原目标，例如「本月对独立练习仍受限」。

同一次追问若保留原任务并新增优先事项，先按各自目标和可用窗口分别取舍。共用同一时段时，按[共同流程的钟面核查](fortune-auditable-reading.md#0-固定输入先划清哪些可以判断)安放任务、收尾和连续休息。先给能否兼顾、优先安排与剩余时间；缩减方案须能独立完成。用户问原判是否改变时，直接点明仍成立的日层排序、月度背景或阶段判断，以及这次安排能影响的范围。

再逐主题提供：

- 主要机会或阻力、推进方向及其原局、运段和当期依据；行动建议不能充当运势判断。
- 主次依据与反向条件：为什么取此方向，主要代价和翻转条件是什么，实际跨界时各段如何不同。
- 个人体感是否与推进一致，例如推进有利但过程费力；引用自述、已确认偏好或可撤回的性情假设，说明其来源。偏好改变可改变体验与策略，不改写已核结构或外部条件。
- 具体能力缺口及影响：原局承受/喜忌、作用主次、运期规则或输入哪一项不足；不能细化的时间尺度只限制相应结论，不以长期背景补成当日顺阻。
- 判断之后给可由现实情况检查的行动建议，不以“让你成长”把阻力美化为好运。

正文在当前对话附依据摘要或 claim ID，索引使用实际登记资料名、固定版本、文件/行号和资料层级。日、周、月、年决定所问时间范围，不规定“一句背景”“若干引用”或研究深度。解读可以在对话中分段交付，独立交付文件仅按用户明确的文档或导出要求生成；仅当覆盖与反审已完成或明确受限时说明对应完成状态，不将资料缺口扩写为精确时点。

## 约束

- 回顾模式标明是已知过去时段的解释；既知事件不包装成独立预测。
- “今天适合做 X 吗”直接给有依据的倾向和前提，并分清传统时段判断与现实行动适配；“建议做”不证明今天有外部好运。
- 复审须核对总体/领域方向有无对应时间层支持、体感是否冒充结果、未知是否被写成中性。只有建议或符号观察，不能称已完成整体运势判断。
- 用户沉默不反馈不作推断，历史校准仍自愿。
