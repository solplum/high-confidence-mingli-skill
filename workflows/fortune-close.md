# Fortune-Close — 收束 Workflow

> **知识来源门（所有引用必读）**：先读 `knowledge/README.md` 并验证 `knowledge/catalog.json`。这条约束优先于下文旧的“原典/权威/书名章节”说法；旧摘要仅作有来源的现代整理，隔离条目不用于解读，未核版本不作逐字古籍引用。直接读旧 references 也必须过此门。


> 由 SKILL.md 在收束条件触发时执行。处理校准信号提取、跨模式关联、memory 更新。
> 输入: 当前会话内容回顾, query_types
> 数据文件: `~/.claude/fortune-telling/memory.md`（本 workflow 产出补丁，由主 agent 直接写入）

反馈解释与修订遵循 [解释标准 v3](../docs/interpretation-standard.md)。分别保存冻结原判、实际结果、主观体验和修订理由；结果与体验可以不同，不能事后换评价对象追认命中。

使用完整条件模型的反馈按 [M0](../docs/model-judgment.md)分别保留盘面事实、原条件模型结果、当时稳健性及实际结果。实际不符如实记录未命中；从结果倒推不可观察的隐藏条件不构成新证据。独立新事实可修订，仍保留原判及失败；无对应真实结果时不报准确率。

## 收束触发条件

- 用户说「结束 / 不问了 / 就到这」等明确收尾语
- 用户明确要求保存某项反馈时，立即按已授权范围处理该反馈。
- 用户切换话题超过 5 轮且未回任何命理话题
- 用户说「谢谢 / 辛苦了」且之后 2 轮内未发起新查询

同一条消息既收束旧问题或要求保存旧反馈，又有新问题时，按各自模式处理。只核实和保存被授权的旧项，同一答复继续完整回答新问题；只给反馈或说谢谢不自动授权写档。

## Phase 1: 校准信号提取

从本次会话的用户反馈中提取:

| 信号类型 | 来源 | 处理 |
|----------|------|------|
| 追问信号 | 用户自发追问某判断方向 | → 写入"运行时画像"当前关注 |
| 确认信号 | 用户说「准」「对」「是这样的」 | → 记录主观反馈，不增加验证次数或准确率 |
| 修正信号 | 用户说「不是X，是Y」 | → 保留原判，记录反馈来源和修订；复查受影响条件及下游判断 |
| 模糊否定 | 用户说「不准」但未具体说明 | → 原样记录否定及信息缺口，复查条件；未能对应具体结果时不强判命中或未命中 |

⚠️ 用户沉默不反馈 → 不做推断，跳过校准。

**累积规则**:
- 同类校准 1-2 次 → 记录，标注「主观反馈，非独立验证」
- 同类校准 ≥ 5 次 → 可合并摘要，保留原记录定位、不同结果和未命中，不抹去反例
- 单次修正信号 → 立即核查并记录处理，不等累积；不覆盖冻结初稿

逐项分清原判的评价对象、目标、领域和时间，以及反馈属于外部结果、目标推进还是个人体验。例如原判“推进有利但过程费力”，需分别核查推进与体验；不能在结果不符时改称“虽然失败但得到成长”。未知结果保留未知，不写成平稳或中性。新确认的偏好可更新后续策略/体感解释，必须注明何时获知，不能回填成原先已经知道。

输出: { calibration_signals: [{ type: string, target: string, action: string, content: string }] }

## Phase 2: 跨模式关联检查

检查两种跨模式关联:

1. **共鸣↔推算**: 共鸣模式中的具体命题与推算模式的相关领域 → 记录问题关联、各自原判与依据定位
2. **运势↔推算**: 运势涉及某领域，后续再问该领域 → 记录时间层、目标和判断是否相容；重复主题或反馈不构成独立验证

输出: { cross_mode_links: [{ concept: string, source_mode: string, target_mode: string, note: string }] }

## Phase 3: Memory 更新

先核对用户已经授权保存的范围；没有保存授权时仅在本次交付中给反馈摘要，不自动写入个人档案。已有授权涵盖的更新直接执行，不将主观认可或跨模式重复当独立验证。沿用现有字段保存原判版本/定位、评价对象与时间、反馈来源/日期、实际结果、主观体验、修订及理由；不另造协议。修改当前画像时保留旧值与修订定位，历史原判不随画像回写。兼容字段名“已验证解释偏移”中的内容仍须注明是自述/反馈还是已检查的规则修订。

生成结构化补丁，由主 agent 直接编辑 `~/.claude/fortune-telling/memory.md`:

```json
{
  "updates": [
    {
      "section": "运行时画像.当前关注|已验证解释偏移",
      "action": "append|update-row",
      "content": "更新内容"
    },
    {
      "section": "校准记录",
      "action": "update-row",
      "key": "条目标识",
      "fields": { "反馈记录": "原判定位与范围；反馈来源/日期；实际结果；主观体验；命中/未命中/信息不足及依据；修订理由与下游影响，保留原判；不是可靠度评分" }
    },
    {
      "section": "共鸣档案",
      "action": "append",
      "content": "| 日期 | 概念 | 逐命题结论 | 核心命题 | 原判/反馈/修订定位 |"
    },
    {
      "section": "跨模式关联",
      "action": "append",
      "content": "| 关联 | 来源 | 目标 | 备注 |"
    },
    {
      "section": "对话日志",
      "action": "append",
      "content": "| 日期 | 查询类型 | 简要内容 | 收束状态 |"
    }
  ]
}
```

action 类型: `append`(追加) | `update-row`(更新已有行) | `merge`(合并多条为汇总) | `archive`(归档旧数据)

## Phase 4: 增长控制

合并和归档也须在本次授权内。只获准记录某条反馈时，保留其他条目和分区原样；本次分析的准备记录只用于当轮，不写入画像或日志。

| 数据区 | 控制策略 |
|--------|---------|
| 对话日志 | 保留最近 30 天，超期归档到 `~/.claude/fortune-telling/memory-archive/YYYY-MM/` |
| 校准记录 | 同类校准 ≥ 5 次时合并为一条汇总记录 |
| 共鸣档案 | 保留最近 20 条，超过后最旧的归档至 memory-archive/ |

输出: { archive_needed: boolean, archive_targets: string[] }

## 各模式收束差异

| 模式 | 收束提取重点 | 写入 memory.md 目标 |
|------|-------------|-------------------|
| 运势查询 | 原时段/领域顺阻与实际结果、体感分别对照 | 运行时画像.当前关注 / 校准记录 |
| 推算查询 | 原推荐及前提、实际选择/结果、体验与翻转条件 | 运行时画像.已验证解释偏移 / 校准记录 |
| 共鸣溯源 | 盘面、解释、现实反馈三层的支持/不支持/部分支持/无法核实 | 共鸣档案 |
| 通用知识 | 仅记录用户关注的概念方向（不校准） | 运行时画像.当前关注 |
| 详批解读 | 各领域原判断、现实反馈、体感和修订，已知事件注明回顾 | 校准记录 + 运行时画像.已验证解释偏移 |

## 校准修正边界

- 先查实际错误：字段、条件或推理错误须修正对应判断及下游；自述/偏好变化只影响相应适配与体感，不能一律调整画像来保住原判。
- 个人反馈不改出生输入、排盘数字、来源用途或公共 references。涉及资料争议时在记录中注明具体条目、反馈与待核范围，不把反馈当作已验证的新规则。
- 交付前核对原判是否可定位、结果与体验是否分开、修订是否注明新增信息及理由、未命中是否完整保留。没有结果信息时明确未知；不以好听解释完成校准。
