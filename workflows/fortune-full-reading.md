# Fortune-Full-Reading — 详批解读 Workflow（第五模式，v5）

> **知识来源门（所有引用必读）**：先读 `knowledge/README.md` 并验证 `knowledge/catalog.json`。这条约束优先于下文旧的“原典/权威/书名章节”说法；旧摘要仅作有来源的现代整理，隔离条目不用于解读，未核版本不作逐字古籍引用。直接读旧 references 也必须过此门。


> 由 SKILL.md §0 路由触发。触发词："详批""批一命""帮我详细看命盘""完整解读""我的命书"。
> 保留 bazi/紫微两 skill 的长文表达体验：全框架、每节全出处、可选历史事件回顾。长文体验不代表预测方法已获验证。
> 输入: 无（全盘展开）
> 数据: `~/.claude/fortune-telling/chart.md` + `~/.claude/fortune-telling/memory.md` + `references/`

## 严格执行层

先读取 `workflows/fortune-auditable-reading.md`。保留以下七节及旧输出 schema，
同时按 `references/auditable-reasoning.md` 保存可审计 ledger 伴随文件。
先独立单盘、再查反证与边界、最后合参；不能把校验通过当成预测准确。
没有机器可读快照或无法运行校验时明确标注，不能声称已通过严格验证。

## 前置检查

1. chart.md 不存在 → 先走 `docs/onboarding.md` 建档，不在本 workflow 内建档
2. 时辰缺失边界：
   - 紫微盘排不出（时辰未知）→ 紫微节整节标注「紫微数据缺失，按缺盘降级」
   - 八字节自动进入**六字模式**（年月日三柱分析，时柱相关内容不判——子女宫、晚年运、部分格局）
3. 历史事件校准为自愿。用户没有样本或不愿提供时继续完成报告，不重复索取；
   未校准不等于已否定或已验证，不能用于升星或计算准确率。

## 节一 · 八字详批

**骨架**（与 bazi skill 第三阶段一致）：日主旺衰 → 十神六亲 → 神煞 → 五行平衡与喜用忌 →
格局判定 → 大运 → 流年

- 知识源：`references/bazi/classical-texts.md`（穷通宝典调候/滴天髓旺衰/子平真诠格局/渊海子平十神）、
  `wuxing-tables.md`、`shensha-table.md`、`dayun-rules.md`

  - 格局判定引《子平真诠》条目，标注成立与成败
  - 每条论断格式：断语 + `> 依据：<典籍名>「原文或规则」`
  - 六字模式时跳过时柱相关步骤并声明

输出 schema: `{ sections: [{ name: string, assertions: [{ statement, citation }] }], liuNianFocus: string }`

## 节二 · 紫微详批

  - 格局有破格警示必须如实说明打折（对照 `patterns.md` 条目的破格条件）
  - 每条论断格式：断语 + `> 依据：《书名·章节》「原文」`
  - 盘缺失 → 整节标注缺失，不硬凑

输出 schema: 同节一

## 节三 · 七政详批

先运行现有 `qizheng_rule_reading`，保留其度主法来源与反条件。若本次明确选择乾元本命宫主参照，调用 `build_chart.py --qizheng-tradition qianyuan-palace-v1` 并读取 `qizheng_traditional_reading`。独立命令与可复现合成例见 `docs/qizheng-traditional-integration.md`。

- 仅 QZT04 的宫主参照分类接入实际盘；字段指针、来源、条件、替代参照、单版影像范围及 CC BY-SA 归属随输出保存。不是把五卡或全书整体认证。
- 正文先写本盘条件式结构，再说明何种字段或参照变化会使解释不适用。只用引擎字段；不自行补造宫主、度主、应期或神煞。
- 缺学派选择、坐标、命度质量、近界、时间不确定、超模型范围等返回 withheld；不要从旧 references 寻找看似更肯定的替代断语。
- 庙乐、旺制刑、升殿、明晦、格局、昼夜优先等旧路由不是本轮可执行的新授权；`references/qizheng/` 仍为门控研究材料，不能直接生成逐曜贵贱病寿婚财断语或伪装成已校勘古文。
- QZT04 不变成个人事件 ledger，不参与跨盘投票或准确率校准。原知识来源门和 classical_quote 禁止门不变。若需要超出结构说明的论断，明确本轮证据不足，不能以免责声明代替缺失证据。
- 盘缺失 → 整节标注缺失；保留不同参照方法，不将宫主法与度主法同名标签混用。

## 节四 · 三盘联系（§9.5 段二）

- 单盘判断冻结后，按领域、时间范围和候选场景对照，标一致 / 冲突 / 范围不同 / 信息不足。
- 检查共同出生输入和资料依赖，不把同指视作独立证实，不以同名术语强行关联。
- 冲突如实并列；合参不可引入单盘未提供的新判断。缺盘继续明确降级。
- 严格 ledger 不含星级或概率；旧消费者的 stars 字段如保留，仅为展示兼容标签，不能表示可靠度。

输出：保留旧 links 的 domains / involved_assertions / synthesis；需要旧 stars 字段的消费者
可保留关联标签，同时附严格 ledger.syntheses。没有已识别的旧消费者时直接使用 ledger.syntheses。

## 节五 · 综合建议

- 事业方向、财运节奏、感情婚姻、健康注意，落到可执行的具体建议
- 每条建议回指节一至节三的 assertion（「依据见八字节·格局」式回指）
- 结尾固定提醒："命理分析仅供参考，人生在于自身的努力和选择。"

## 节六 · 历史事件校准（bazi 校准法）

仅在用户愿意时执行。先冻结判断、时间窗、事件类别及未命中标准，再看反馈；
完整记录命中 / 未命中 / 信息不足，不只挑命中的部分。用户已提供的历史事件只能用于回顾，
不能包装成独立预测。修改解释后保留修订版本，不在同一批事件上声称完成再次验证。

- 用户无样例、不愿提供或跳过：继续交付，不再次追问，不将其转成升降星依据。
- 校准只更新用户同意保存的解释记录，不改引擎盘面或 references 原始资料。

## 节七 · 斯多葛收束（§9.5 段三）

- 全篇断语按 §9 转写（典籍引文原样保留）；每大节附「你可以把握的是」练习建议
- 解释器校准：按 memory.md「运行时画像」调整表述形态（先内化再输出者收着说，直出型直接说）

## 约束

- 详批是长文模式：单节可以长，但每节必须以「依据」行收口，禁止无出处断语
- 与推算查询的边界：用户追问单个问题 → 建议转推算查询（fortune-specific），不在详批内展开新问题
- 详批结果的关键结论写入 memory.md「跨模式关联」（由收束 workflow 处理）
