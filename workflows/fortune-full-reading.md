# Fortune-Full-Reading — 全盘详批范围

先读取 `workflows/fortune-auditable-reading.md`，按共享严格层实际建立快照、workpad、单盘记录和复审处理。全盘详批增加的是覆盖范围；其他个人模式执行相同质量标准。资料引用按 `knowledge/README.md` 实际登记属性和用途处理。

输入为用户的全盘解读要求及现有档案。chart.md 不存在时读取 `docs/onboarding.md`；只有旧 Markdown 或缺原始输入时交付明确受限的结果，不反推出生信息。时辰未知时保留八字六字模式，紫微及七政依赖时间的部分缺失；校准自愿，用户无样例时直接继续。

## 一、八字详批

覆盖：月令/透干/通根/藏干与冲合事实 → 旺衰证据与争议 → 十神关系 → 调候、格局候选与喜忌的适用条件 → 已输出神煞的有限含义 → 大运与所问流年。

按共享流程的八字检查项逐项研究。自动 `bazi_core_reading`、`strength_reasoning` 与格局候选提供底稿，不代表全局旺衰、调候、喜忌已经解决。用本盘具体支持和反向条件解释候选之间的关系；缺规则或效力条件时逐项暂不判，不用一个固定格名概括全部。

## 二、紫微详批

覆盖：命身事实 → 十二宫逐项记录 → 重点领域的宫位关系与三方四正 → 原始亮度和固定本命四化 → 有实际字段与获准规则的大限/流年 → 候选格局的必要条件与破格检查。

四宫 `domain_reading` 只覆盖命财官迁主题，其余八宫另查适用资料或记录具体缺口。空宫借星、完整四化与辅煞组合不自动补成确定解释。格局程序命中只是待审候选，先查来源是否获准，再核成立、排除与反向条件。保持本仓固定本命四化口径，不混入宫干飞化、自化或未输出流曜。

## 三、七政详批

先读 `docs/qizheng-rule-profiles.md` 并使用现有 `qizheng_rule_reading` 的度主法、来源和反条件。仅用户明确选择乾元本命宫主参照时，按 `docs/qizheng-traditional-integration.md` 实际调用 `build_chart.py --qizheng-tradition qianyuan-palace-v1` 或对应独立命令。

记录实际命度、立命宫、星框、昼夜与已启用的结构关系。QZT04 仅是一个参照分类；保存字段指针、条件、替代参照、单版影像范围与 CC BY-SA 归属。conditional 可解释为采用此盘及此法的条件结构；withheld 逐项说明具体缺口。该面板不进入个人事件 ledger、合参投票或校准命中。

时间误差与敏感性按共享流程实际执行。庙乐、旺制刑、升殿、明晦、完整格局、行限、昼夜优先等未启用部分保留缺口；不得从旧参考绕出更肯定的人生断语。未选乾元法时保留原度主法，不自动混用。

## 四、三盘对照

单盘初稿冻结、复审发现处理后，只对相同领域和时间范围、相容场景下的可用判断进行对照。记录一致、冲突、范围不同或信息不足及共同依赖。保留具体分歧和边界，不新增任何单盘记录没有支持的断语。缺盘可以交付可用范围；受用途限制的面板单独呈现。

## 五、主题综合与现实核查

根据实际证据展开事业、资源/财务、感情关系等相关主题。详批逐项记录主题是否有支持，健康仅提供一般生活反思，不能由盘面推出诊断、病程或用药。每个主要主题按“具体解释 → 依据与关系 → 反向条件 → 适用边界 → 现实核查”组织，回指单盘 claim 或模块记录。

低风险行动贴近用户实际问题；已知经历仅作为现实输入，不写成算出的发现。共用限制集中交代，主题详析给出本盘的具体内容。

## 六、自愿反馈与历史回顾

用户无示例、不愿提供或跳过时继续交付，标注未做。愿意时先冻结判断、时间窗、事件类别及未命中标准，再完整记录命中、未命中和信息不足。已知事件只能用于回顾，修订保留版本；保存反馈遵循用户授权，不改变引擎盘面或公共资料。

## 七、斯多葛收束与交付

开头概括最值得看的主题及判断范围，正文充分解释，最后提供可控的现实行动。附录给覆盖矩阵、具体缺口、冲突、引用索引、复审处理和校验状态，并链接实际证据文件。

旧输出 schema 如有已识别消费者，可保留 sections/assertions、liuNianFocus 和 links 的显示结构，同时附实际 claim/模块定位与严格证据记录。旧 stars 只可保留既有展示值，不能用盘数或核查结果计算可靠度；没有旧消费者时直接使用 ledger.syntheses。正文或兼容字段不能丢失来源属性和用途限制。

## 完成条件

使用共享流程的完成清单。七节是覆盖框架，所有章节都出现不等于完成；每个必要项须有实际分析或具体缺口。重要问题尚未核查时继续，无法检查时明确为受限报告。用户追问单个主题时转入相应问题范围，复用有效证据并研究新增部分，不能因此降低核查要求。
