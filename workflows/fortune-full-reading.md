# Fortune-Full-Reading — 全盘详批范围

先读取 `workflows/fortune-auditable-reading.md`，按共享严格层实际建立快照、workpad、单盘记录和复审处理。全盘详批增加的是覆盖范围；其他个人模式执行相同质量标准。解释与裁决遵循 [解释标准 v3](../docs/interpretation-standard.md)，资料引用按 `knowledge/README.md` 实际登记属性和用途处理。

输入为用户的全盘解读要求及现有档案。chart.md 不存在时读取 `docs/onboarding.md`；只有旧 Markdown 或缺原始输入时交付明确受限的结果，不反推出生信息。只知出生日期时保留八字六字模式，紫微及七政依赖时间的部分待核。校准自愿，用户无样例时直接继续。

## 一、八字详批

覆盖：月令/透干/通根/藏干与冲合事实 → 旺衰证据与争议 → 十神关系 → 调候、格局候选与喜忌的适用条件 → 已输出神煞的有限含义 → 大运与所问流年。

按共享流程的八字检查项逐项研究。自动 `bazi_core_reading`、`strength_reasoning` 与格局候选提供底稿，不代表全局旺衰、调候、喜忌已经解决。用本盘具体支持和反向条件解释候选之间的关系；缺规则或效力条件时逐项暂不判，不用一个固定格名概括全部。

辛日出生子月的完整整体／发展配置，按 [M0](../docs/model-judgment.md)及QX登记卡另核本命与运期适配。完整源内评价可形成有边界的模型方向，异读和未决作用同时说明；它不把详批的感情、健康等领域一并定性。

问一生走向或跨多个大运时，先冻结本命判断和要比较的目标，再按[原折月年龄窗](../docs/time-contract.md#八字大运年龄)逐一核对所问范围内已排出的大运。用 BJ06 检查每一运的干、支怎样改变同一原局路径，并列出有依据的支持、限制或决定性缺口。QX 适用时按[大运逐窗入口](../docs/bazi-qiong-xin-zi.md#只问大运或比较多个大运)逐运核正支、反条和异读，说明方向在哪里改变。正文交代原局判断、分阶段的实际方向、交运附近可能改变结论的相邻分支，以及未排出年龄的范围。保留每运的判断及依据后，可合并连续同向阶段。问具体年份再按实际年界另核流年。

请求的折月年龄范围已核定时，调用 [大运范围入口](../docs/time-contract.md#八字大运年龄)列出每个出生候选与请求相交的运窗及表外缺口。逐窗回填判断，读到只覆盖一部分的首尾运。实际公历交界未能核准时，用原折月范围说明各运的条件与交界的不确定性。原运表可读但缺某运的判断时，先补读再写连续同向或变化；只有该运的适用证据仍缺时，才注明缺口。

若所问目标依赖酉官路径，按[甲日酉官判读](../docs/bazi-officer-luck.md)核实际卯运和退出条件，相邻运各自判断。

出生时刻有误差、只确认民用时辰或同日钟面区间时，先用[折月候选的配对方法](../docs/bazi-qiong-xin-zi.md#出生时刻有误差时比较大运)找出实际可达的四柱与起运窗。四柱相同也逐一核起运不同的配对。用各窗的实际折月起止比较同一目标，写出候选何时共同支持某个方向，何时因交运分开。缺枚举或见证时，说明会影响哪些运段。

## 二、紫微详批

覆盖：命身事实 → 十二宫逐项记录 → 重点领域的宫位关系与三方四正 → 原始亮度和固定本命四化 → 有实际字段与获准规则的大限/流年 → 候选格局的必要条件与破格检查。

四宫 `domain_reading` 只覆盖命财官迁；其余八宫及新增分量主题实际读取 `life_reading`，按[已批准范围](../docs/approved-life-domains.md)查询对应卡、核角色和反向条件。空宫借星、完整四化与辅煞组合不自动补成确定解释。格局程序命中只是待审候选，先查来源是否获准，再核成立、排除与反向条件。保持本仓固定本命四化口径，不混入宫干飞化、自化或未输出流曜。

已确认原民用生日和单个时辰时，按[时辰复盘入口](../docs/ziwei-life-reading.md#只确认民用日期和时辰)核本命和所问年的原生大限。确认出生在同一公历生日内的民用钟面区间时，按[区间候选入口](../docs/ziwei-life-reading.md#已知民用出生钟面区间)取得各候选的原生大限。逐候选选实际年度窗并核相关领域。所问结论在候选间变化时，交代各自成立的出生时间范围。

详批明确询问流年或限定年份内的具体目标时，按[紫微动态时间合同](../docs/ziwei-dynamic-facts.md)逐段生成独立年层事实，再按[`life_reading` 入口](../docs/ziwei-life-reading.md)传入快照和动态 JSON。核对年层宫位与实际本命星的附着，按适用的 ZW-D/E 卡检查角色、投入与反向条件。追问某一公历年的当前大限时，传本次的 `--analysis-year` 并复核输出所标年份。

流年请求跨动态工程范围时，按[部分覆盖办法](../docs/ziwei-dynamic-facts.md#跨动态历法覆盖边界)交付实际可读的流年段和缺口，并独立核对所问各年的大限。

问一生走向或同一目标跨相邻大限时，按实际年度窗分别核所问目标的支持、制约或决定性缺口。按[已批准的阶段条件](../docs/stage-and-spouse-models.md#紫微大限与本命关系)指出原支持何时退出，下一阶段是否另有支持或反条。若公历年切换大限时农历年／月事实仍相同，归因给实际变化的阶段条件，并保留各自适用的时间和领域。

问一生或要求读完整大限时，从已核 `stages[].legacy_stage.window` 对照所问范围，逐窗回填实际宫位、相关条件或具体缺口，包含只覆盖首尾窗一部分的情况。出生后至首限前、末限以后若在所问范围，单独标出无已排大限的区间。回顾式比较可写某阶段对指定目标的条件，实际经历按用户提供的证据另核。正文合并多个未决阶段时，仍说明它们为何缺同一目标的方向依据。

## 三、七政详批

先读 `docs/qizheng-rule-profiles.md` 并使用现有 `qizheng_rule_reading` 的度主法、来源和反条件。仅用户明确选择乾元本命宫主参照时，按 `docs/qizheng-traditional-integration.md` 实际调用 `build_chart.py --qizheng-tradition qianyuan-palace-v1` 或对应独立命令。

记录实际命度、立命宫、星框、昼夜与已启用的结构关系。QZT04 仅是一个参照分类；保存字段指针、条件、替代参照、单版影像范围与 CC BY-SA 归属。conditional 可解释为采用此盘及此法的条件结构；withheld 逐项说明具体缺口。该面板不进入个人事件 ledger、合参投票或校准命中。

时间误差与敏感性按共享流程实际执行。庙乐、旺制刑、升殿、明晦、完整格局、行限、昼夜优先等未启用部分保留缺口；不得从旧参考绕出更肯定的人生断语。未选乾元法时保留原度主法，不自动混用。

## 四、三盘对照

单盘初稿冻结、复审发现处理后，只对相同领域和时间范围、相容场景下的可用判断进行对照。记录一致、冲突、范围不同或信息不足及共同依赖。保留具体分歧和边界，不新增任何单盘记录没有支持的断语。缺盘可以交付可用范围；受用途限制的面板单独呈现。

## 五、主题综合与现实核查

根据实际证据展开事业、资源/财务、感情关系等相关主题。逐领域给主要优势、制约、适配方式与发展代价；有依据时归纳总体方向，不把人的价值概括为好命或坏命。详批逐项记录主题是否有支持，健康仅提供一般生活反思，不能由盘面推出诊断、病程或用药。每个主要主题按“主结论及评价对象 → 依据与主次比较 → 代价与翻转条件 → 适用边界 → 现实核查”组织，回指单盘 claim 或模块记录。

先冻结结构判断，再用有来源的用户自述、已确认偏好或可撤回的性情假设解释策略适配、体感与行为成本；未知时保留分支。分别说清长期结构、所问运期与现实目标，推进有利不等于过程轻松，偏好也不产生外部机会。性格不仅用于润色措辞，但不能补齐喜忌、效力或时间层依据。

长期问题有多个目标时，分别核每个目标在哪些阶段有依据、何时退出。例如某阶段有筹办新安排的支持，维持已有交接仍按自身条件给方向或说明具体缺口。八字大运和紫微大限各用实际起止，在重叠时段对照同一个目标。

多个目标须先后完成时，先核哪一步能够独立开展、哪一步依赖已完成成果与现实许可，再给可行次序。某一阶段的依据退出时，说明它具体影响哪一步。仍可用的成果及仍有效的安排继续按各自条件评估。

长期分析兼问近期安排时，按[共同流程的钟面核查](fortune-auditable-reading.md#0-固定输入先划清哪些可以判断)检查已确认的时段、次数、授权和连续休息。两段工作能否算作两次安排，取决于用户要求的间隔或不同日期。时间刚好够用时，明确超时如何保住硬性安排。

相邻阶段方向相同但依据或异读改变时，交代具体切点及影响。普通正支退出时，另核是否出现负向条件。给选择时，区分按已知资源可以维持的做法，以及增加投入还需要哪些依据。

支持与反向条件须在同一领域、目标和时间内比较，不按盘数或标签判好坏。局部缺口只限制对应判断；必要条件、特指反条或同等适用的竞争分支未决时，明确该项无法定性；其余未决作用按M0另报稳健性，不称平稳或好坏相抵。低风险行动放在判断之后，贴近用户实际问题；已知经历仅作为现实输入，不写成算出的发现。共用限制集中交代。

## 六、自愿反馈与历史回顾

用户无示例、不愿提供或跳过时继续交付，标注未做。愿意时先冻结判断、时间窗、事件类别及未命中标准，再分别记录实际结果、主观体验、命中/未命中/信息不足与修订理由；不以“结果不好但成长了”追认命中。已知事件只能用于回顾，修订保留原判及版本；保存反馈遵循用户授权，不改变引擎盘面或公共资料。

## 七、斯多葛收束与交付

前两段给实际支持的总体归纳、主要领域结论及范围；不能归纳总体时明确原因，其他领域仍直接回答。用户同时问一生概况和限定区间时，局部阶段方向在开头就标明已比较的区间和所评价的目标。完整正文直接在当前对话充分解释优势与代价、目标推进与体感的异同，最后提供可控的现实行动。理解结论所需的具体缺口、冲突与依据摘要也在对话说明；完整覆盖矩阵、引用索引、复审处理和校验状态保留内部，用户要求查看时再提供实际证据定位。仅按用户明确的文档或导出要求额外生成独立交付文件。

旧输出 schema 如有已识别消费者，可保留 sections/assertions、liuNianFocus 和 links 的显示结构，同时附实际 claim/模块定位与严格证据记录。旧 stars 只可保留既有展示值，不能用盘数或核查结果计算可靠度；没有旧消费者时直接使用 ledger.syntheses。正文或兼容字段不能丢失来源属性和用途限制。

## 完成条件

使用共享流程的完成清单。七节是覆盖框架，所有章节都出现不等于完成；每个必要项须有实际分析或具体缺口。复审须能从前两段识别主结论及对象，并检查主次比较、个人背景身份、未知与中性的区分；仅有术语、建议或优缺点罗列不算已完成领域判断。重要问题尚未核查时继续，无法检查时明确为受限报告。用户追问单个主题时转入相应问题范围，复用有效证据并研究新增部分，不能因此降低核查要求。
