# Claim ledger v1：使用说明与验证边界

这是工程协议，不是古籍，不更改 `references/bazi`、`references/ziwei` 或 `references/qizheng` 原始资料。原排盘输出、chart.md、memory.md 与七节详批兼容。个人分析按 `workflows/fortune-auditable-reading.md` 保存证据与工作记录；符合现有用途的判断使用 ledger v1，module-only 等受限模块保存原始证据与人工解释记录，真实用户档案存放在 skill 仓库之外。通用知识问答不要求私有 ledger；涉及个人盘面对照时，该部分进入个人分析流程。无机器快照或无法运行校验时保留明确受限记录，不声称已完成机器校验。

解释与裁决遵循 [统一标准 v3](../docs/interpretation-standard.md)，区分盘面事实、可定位传统释义、作者现代转译与条件综合，先回答问题再给建议。个人结论分别核对外部形势、目标推进与代价、主观体感，回指总体/领域评价、主次依据及有来源的性格/偏好条件。现代用语无需逐句注册，但作者转译须保留实际依据和推论身份；它不改变本协议的规则摘录、来源用途、依赖和状态检查。

## 文件结构

可运行的样例：`examples/claim-ledger.example.json`。它仅含合成规则和占位字段，不是完整命盘，也不是命理准确性的案例。验证：

```
python3 scripts/validate_claim_ledger.py examples/claim-ledger.example.json --root examples/ledger-fixture
python3 -m unittest discover -s tests -p 'test_claim_ledger.py' -v
```

真实使用时，将所用引擎 JSON 快照和实际引用资料副本放入本次私有证据目录，计算各文件 SHA-256。先运行 `python3 scripts/build_chart.py ... --format json` 获取三引擎快照（默认文本输出仍兼容），事实以 JSON pointer 连接。缺失紫微时值为 null 并附原因，不得补造事实。快照应另存运行命令、版本和口径说明，不能把这些元数据当排盘事实。不要把含个人资料的 ledger 或快照提交到公共仓库。

顶层：`schema_version: 1`、`purpose: reading | synthetic_test`，以及以下数组。每张表的 id 唯一。

- **sources**：id、kind（chart/reference）、path（相对 --root）、sha256。路径含符号链接时也必须仍在根目录内。只读普通文件，不执行其内容。chart 来源还必须声明 system、scenario_id、pointer_prefix（如 /bazi），事实须与绑定一致；同一路径不能重贴标签当成另一候选场景，同一文件的不同体系前缀不能重叠。每个场景分别保存快照，即使数值恰好相同。hash 只证明此次快照没有改变，不证明上游真实性。
- **scenarios**：id、label、time_basis、assumptions。每个实际生成的候选输入与口径一个场景；未检查的争议写入限制，不伪造候选。
- **facts**：id、system（bazi/ziwei/qizheng）、scenario_id、source_id、pointer、value。必须逐字段等于 chart JSON；支持字典和数组指针。计算结果也是在指定模型下的结果，不等于现实事件证据。
- **rules**：id、system、source_id、school、locator、start_line、end_line、quote。行号从 1 起；引文必须逐字存在于该行区间。locator 写原书/整理本/章节等真实定位；校验器不替你核实版本权威或规则是否适用。
- **claims**：id、system、domain、time_scope、statement、status、fact_ids、rule_ids、depends_on、scenario_ids、conditions、counterevidence、alternatives、boundary、explanation、limitations。无依赖仍填空数组。explanation 有 plain / technical / action 三段；在现有授权与状态允许的范围内，说明资料原意、作者现代转译和综合理由，规则quote仍保留实际来源文字，不为转译伪造引文。
- **syntheses**：id、claim_ids、relation（agreement/conflict/different_scope/insufficient）、explanation、shared_inputs、limits。至少两个不同体系，合参不可反过来充当单盘证据。agreement 和 conflict 都要求同领域、同时间范围、同场景集合且成员已有判断。范围不同用 different_scope，任一成员缺相应判断时用 insufficient。

`status`：supported = 在已核对的规则及场景内有支持；conditional = 有条件或缺口；withheld = 暂不作判断。三者都不是预测可靠度。

证据状态与评价方向分开：supported可以支持阻力，conditional也可有范围清楚的局部方向；withheld不表示平稳或中性。按v3在现有statement/explanation与workpad记录评价对象、目标、时间层、裁决及其主次依据，无需新增schema或评分字段。同轴反向条件无法比较时明确未决；机器校验不判断比较是否充分，需人工复审。体感和目标适配不替代外部机会、效力或当期规则证据。

`boundary`：stable = 对所有已列候选都有事实链支持；conditional = 只在部分候选成立；unassessed = 尚未检查。非 stable 不能标 supported。声明 stable 仍需人工比较实际解释是否相同，脚本只能查场景覆盖。

`counterevidence` / `alternatives` 不可空。确无足够资料时明确“未能检查，因为缺少 X”，不得写成“没有反证所以成立”。这两个字段必须人工复核内容，不以非空就算研究完成。depends_on 仅限同体系判断，禁止循环；依赖须覆盖当前判断的场景并使用相同 time_scope，不得将 withheld 或 conditional 依赖偷偷升级。跨时间层的依据应作为原始 facts 引入并说明条件，不用不同时间范围的 claim 偷渡。

## 可以自动检查什么

重复与悬空 ID、字段引用值、引用文件 hash、行范围和引文、与显式来源绑定不符的体系/场景混入、依赖循环、声明的场景覆盖、范围不一致的合参，以及显式概率/星级字段。账本和命盘来源的 JSON 对象须使用唯一键，冲突字段须回到原记录核对后修正。CLI 返回 JSON；通过退出码 0、校验失败 1、账本输入无法解析 2。无网络请求，无第三方运行依赖。

可识别的总控快照会按实际字段分区核对体系，包括各盘底稿和候选分区。旧档缺派生 `time` 时也核对体系。七政独立传统参照入口的原生盘、参照面板及独立民用时辰／钟面区间的采样快照识别为七政。八字独立民用生日、时辰和钟面区间入口的快照识别为八字。紫微原生引擎快照、独立出生区间快照、领域续算面板和独立动态适配器识别为紫微。

引用七政条件释义时，核对它记录的宿、度主五行、立命宫、宫主和实际生克分类。乾元参照核对已存的原盘指纹、所选比较曜及引擎五行，并按既有宫主口径核分类。旧档缺指纹时仍核对已有盘面归属。含出生误差的总控中心继续按原暂缓状态理解，独立采样点可用的解释各限该点。引用样点的规则摘要时，另核对应面板。引用单项释义时按该项核对，原生字段可单独引用。

引用总控本命派生面板时，核已有八字四柱、模型出生归属，以及紫微已存出生字段、实际宫位与被引用阶段的年口径。明确错贴的派生判断回到原盘重算。独立引用原生字段时仍按原字段核对，旧档缺少派生副本时保留可复核的部分。

总控紫微及已确认民用钟面区间的所选候选，其 `life_reading` 本命领域证据按同一份原生盘重放。引用 `domains` 的宫位行、实际星表、主星主题、疾厄边界或 `modules` 的 ZW-D01～08 时，按所引路径核对该值。即使两盘宫位名称和地支相同，邻日派生星表或主题也须回到原盘复核。引用未受影响的宫位或原生字段可独立核对。用途受限的解释仍按原范围记入人工解读。

总控或独立出生候选引用八字配偶支持面板时，按可核原盘或重放候选复核已存性别、财星、反条及筛查状态。明确来源未通过时，留存暂缓及实际缺口。核对通过仍需按该规则独立复审所问发展目标与官用假说。

引用八字子月辛金本命模型时，按原盘或已核出生候选重放所引用的条件方向、所选分支与特指反条。已知有出生误差的中心仍按参考范围处理。原四柱和其他独立模块可分别引用。日、月及运期的完整方向另走实际时间层续算。

总控紫微引用长期阶段或本命婚姻模型时，按原生星表、亮度、四化和所用年度窗重放被引用部分。宫位布局或年份相同也要核具体规则所用事实。引用单独的本命婚姻判断时，独立的大限年度缺口仍按阶段处理。

总控紫微引用亲密协商或表达判例时，按该盘的实际星曜和固定本命四化复核所引判例。静态总控档的年度主动申请判例须保持暂缓，有独立动态依据时应引用实际查询点的续算。旧档缺可选说明字段时复核仍保存的判例条件和状态。

同一场景引用多份无出生误差的快照时，按仍可核的民用时刻、北京时间或八字原生出生瞬间核对。七政独立入口的出生钟面按该入口的北京时间理解。并存的记录须与彼此及可核的原民用输入吻合，明确冲突单列，等价偏移表示可同时保留。八字与紫微证据还核对已记录的性别、所选口径、排盘分钟和原生排盘日期及紫微时辰。多份紫微证据还核对用于旧大限的原民用出生年，即使排盘钟面相同也须保留跨年差异。多份七政证据核对已记录的出生经纬度、计算配置和 DUT1；同一七政盘可用于多种已准传统参照。出生误差、各独立候选或旧档缺可核字段时，按已有证据复审。身份、排盘口径及候选的实际覆盖仍须复审。

总控档保留的 IANA 时区数据指纹与本次实际加载的数据一致时，用该数据把原生出生瞬间转回原民用钟面，核对已存的回拨分支。时区数据缺失或版本不同时，保留档内可核的一致性，原时区规则需另行复核。

独立八字快照有可核的民用半开区间时，按事实指针取指定候选的可达窗、指定出生窗或折月出生段。整份快照层面的事实使用全部可达窗的并集。按实际 UTC 累积同场景交集，要求区间重叠且对应的民用偏移相同，保留子时等非连续范围的空档。该场景也有已核精确出生瞬间时，精确点必须在交集内，右端不包含。按民用口径排盘的八字、紫微精确快照也核对原民用钟面与已核瞬间所对应的有效偏移。已记录的民用口径和性别参与同场景的八字与紫微来源核对。旧档缺区间时保留体系识别，其出生范围仍需复审。

独立八字快照原民用输入完整且可重放时，按原日期、时辰或钟面区间核对候选四柱与窗口。有原折月候选表时一并核对折月见证。引用候选解读核心的 `facts`、整个解读对象、候选或候选数组时，核对引用内留存的核心事实是否来自各自的重放候选。旧档缺解读核心时可继续引用已核的候选与窗口。缺重放所需的输入时，可核的存档范围仍作证据，原输入与候选的归属待查。

紫微独立区间同样按事实所指取已记录的实际半开出生窗。整份区间事实取各候选可达窗的并集，候选或选定时辰的续算面板取该候选可达窗，指向单一子窗的事实取该子窗。同一场景按已知民用偏移与其他出生证据累积交集，并核对已记录的出生年、排盘日期、时辰与性别。领域续算面板明确记录同一个最早和最晚出生瞬间且出生时刻无误差时，也可参与精确点核对。独立原生引擎快照按明确保存的出生年、排盘日期、时辰和性别核对。缺排盘口径或实际出生范围时保留未知，查询时刻不用于填补出生范围。

紫微续算盘只确认民用日期和时辰时，仍可用已保存的半开钟面范围核对同场景的民用证据。已知有效偏移的八字出生窗或精确点须与该日期、时辰相容。历史回拨按各段有效偏移分别核对，保留子时的两个钟面区间。缺钟面范围或无可核有效偏移时，该项保留未知。

独立动态适配器的出生输入、附带原生输入和出生标头齐全时，先核三者一致，再按排盘日期、时辰、性别和原民用出生年核对同一场景。不同查询日期可引用同一出生场景，动态查询钟面只用于定位查询。旧档缺出生依据时保留体系核对，出生身份留待复审。

七政总控、独立采样快照或从文本证据中单独保存的采样块引用指定样点时，核该样点保存的民用钟面、UTC 及原生儒略日，并按实际 UTC 单点核同一场景的证据是否相容。采样统计、整段范围及候选列表仍按其原有用途记录，不能据某个样点的校验推定实际出生时刻、整段覆盖或规则效力。

有总控原输入时，另核采样区间是否围绕同一出生中心，并按已记录的原误差核宽度。已确认民用时辰或钟面区间的存档还要核外层实际民用段，引用的内部样本须属于该段及可复核的原钟面范围。原时区可核时，按该时区确认样点的民用偏移及已保存的回拨分支。原经纬度和计算参数可核时，按样点瞬间重放命度及昼夜。单独保存采样块时保留其 `input`，用于同样的复核。有外层原档时，核两处共用的计算输入是否相合。旧采样块缺输入时，按块内实际见证核对，原地点与时区回原档复核。

直接引用出生时间有误差的七政中心盘字段时，核对可用的原始钟面和原生 UTC 儒略日，再用生成该字段的实际计算点核对同场景相容性。仅引用采样汇总或规则暂缓状态时无须绑定中心点。通过计算点核对后，实际出生时刻及个人规则适用性仍须分别复审。

总控枚举快照中，八字候选事实按候选 ID 回查原枚举窗，紫微候选事实取其所关联原枚举窗的并集。完整枚举的实际 UTC 窗参与同一场景的交集与精确点检查，按记录保留右端包含状态及单点窗。固定民用偏移取已记录值，夏令时重复时段的分组窗若缺逐段偏移则保留未知。真太阳时的数值见证只提供已记录的排盘离散输入，出生区间仍需复审。

总控档引用八字候选时，核已有四柱与原枚举字段。引用该候选的解读时，也核所附的四柱事实及被引用模型保存的候选归属。引用紫微候选时，核已有排盘日期、时辰和原民用出生年，引用所附盘面或解读时也核原生盘的出生字段。引用阶段时核已有原生年龄与阶段合同，引用判例时核所附宫位与原生盘的位置。引用整个候选数组时逐条核对，仍按各自可达窗解释。旧档缺派生字段时使用仍可核的原生字段，并写明需要回原档确认的部分。

总控紫微候选续算面板另存实际出生窗时，引用整个面板取这些窗的并集，引用单窗字段则取该窗。账本核对记录的排盘口径和民用窗的逐段有效偏移，保留间隙及开闭边界。旧面板只有出生首尾包络时，仍须回到原档核对实际出生覆盖。

**不检查**：快照是否确由声称的命令执行生成（复制后重新命名的文件仍需人工核查）；任意快照的场景声明与未知字段前缀是否真实；天文/历法计算本身是否正确；源文件真实性；所谓经典是否真的原典；规则前提是否语义满足；反证搜索是否充分；自然语言是否夸大；预测能力；健康、财务等建议是否合适。未知附加字段保留兼容性，不意味着它们经过验证。不能将“校验通过”宣传为“算得准”。这是一致性检查，不是抗恶意伪造的签名证明。除合成结构样例外，examples/engine-reading 包含实际引擎的虚构输入端到端演示；仍未完成真实个案的解读质量或命中率评测。

## 与 fortune-observatory 的对照与取舍

对照了该项目 `apps/api/reading_agent.py` 的 `build_reading_system` 和 `tests/verified/test_split_reading_contexts.py`。借鉴的是“单体系上下文隔离 + 测试防混入”这一设计模式，没有复制其运行代码、提示词或典籍文本。

不照搬其混合模式“紫微为主、八字印证”的默认优先级，也不沿用把 qizheng.chart 路由到紫微语境的分组。七政的星框、日月处理与用/仇口径需要按版本分别核查，不能因名字相同就当作可替换数据。后续如移植素材，应逐文件核对许可证、来源版本、语义与回归样例；本次新增实现完全独立。

## 个人分析入口与工作记录

详批、具体问题、运势及共鸣对照均先执行 `workflows/fortune-auditable-reading.md` 的共同流程；各分支仅决定本次问题和时间范围。可进入 ledger 的重要判断沿用 v1 连接实际字段、登记规则、条件、反证、替代解释和场景。用途受限的原生模块及其人工解释在工作记录中保存唯一ID、原始面板定位与同等依据摘要，不为凑齐文件创建假claim、伪造引文或改写模块状态。supported 始终只表示给定规则和场景内的支持，不表示现实预测可靠度。

按 `templates/reading-workpad.template.md` 保存本次执行记录、主题覆盖、检索结果与无匹配项、单盘初稿、现代转译与综合理由、评价与裁决、独立复审发现及处理结果，并连接 ledger、原生模块、来源副本和最终正文。结构判断先冻结，再引入有来源的现实性格与目标作体验/适配解释；原判、实际结果、主观体验和修订理由分别保留。自动未编码或未裁决的内容可在获准方法与资料范围内继续人工研究，实际缺失字段、必要条件和来源限制仍约束相应解释。工作记录补充人的语义审查，不改变 v1 字段，也不把隐藏思维过程当交付要求。

跨盘对照可定位合法ledger claim或原生模块人工解释记录，并保留各自用途和共同依赖。v1 JSON的syntheses仍只引用本ledger合法claim_ids；涉及原生模块的对照保存在workpad或报告，不把模块记录伪装成ledger claim。七政已有的禁止个人事件claim、合参投票或校准命中等限制继续按对应模块执行。

完成按相关主题的检查充分性判断：有可查的字段和来源，条件与反向解释已检查，实际边界已比较或明确缺口，复审发现已处理，正文与最终证据一致。审核者须从开头指出回答实际问题的主结论及其对象，检查评价方向、主次和体感各有依据；仅有建议、两面清单或语言丰富不足以完成。机器校验结果和未运行项如实记录；篇幅、引用条数及耗时都不能单独证明完成。中断时保存已完成项和待办，不将未检查项记为通过。

## 来源门升级

ledger 现在自动检查已登记来源的摘录标记与隔离片段。引用旧整理文件需 attribution_kind=registered_source_excerpt 及登记 source_label；仍不证明原书真实性或语义适用。见 knowledge/README.md。

来源门加强：隔离按已知来源的行范围而非完整短句匹配；未知引用必须显式标为 caller_declared_unverified，且CLI列出对应rule IDs。本版不存在可自填元数据升级的原典认证路径，classical_quote 暂不可用；普通资料摘录不受此限制。
